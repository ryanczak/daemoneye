# Bug 1 on phase-05: E2E transcript pasted into Update Log is not verbatim `/tmp/e2e-05.txt`

**Severity:** blocker
**Status:** open
**Filed:** 2026-08-08

## What's wrong

The phase's `### Update — 2026-08-08 06:38 (end-to-end verification)` entry
(`docs/dev/milestones/M12-tmux-integration/phase-05-list-panes-upgrade.md`,
lines 502–558) claims to be the verbatim contents of `/tmp/e2e-05.txt`. The
file still exists on disk (mtime `2026-08-08 00:02:40 -0700`, consistent with
the run) and does **not** match what was pasted.

`diff /tmp/e2e-05.txt <(sed -n '502,558p' phase-05-list-panes-upgrade.md)`
shows a mismatch on 7 of the 57 lines — the seven `test result:` summary
lines from the `cargo fmt`/`build`/`clippy`/`test` gate block:

File (`/tmp/e2e-05.txt`, genuine):
```
test result: ok. 1182 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 4.11s
test result: ok. 0 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.00s
...
```

Pasted into the phase doc:
```
test result: ok. 1182 passed; 0 failed; 0 ignored; 0 measured; 1181 filtered out; finished in 4.11s
test result: ok. 0 passed; 0 failed; 0 ignored; 0 measured; 0.00s
...
```

Two tells that this is retyped/reconstructed text, not a paste:

1. The full, unfiltered `cargo test` in the E2E block (§ End-to-end
   verification, no test-name argument) can never report `1181 filtered out`
   — that count is the signature of a single-test-name-filtered run (1182
   total minus the 1 test that matched a filter), which is what the M1/M2
   mutation-test invocations later in the same block produce. It leaked into
   the wrong summary line.
2. The other six summary lines are missing the `filtered out; finished in`
   clause entirely, which `cargo test`'s libtest harness always emits — no
   real run produces that truncated form.

This is the same failure class the project already bounced phase-04 for
(bug-04-2): a transcript that is retyped, paraphrased, or reassembled instead
of mechanically captured fails the DoD box even when every underlying claim
in it is true. `STANDARDS.md` §1: "A transcript that is retyped, paraphrased,
summarised into prose, or assembled from more than one run fails this box
**even when every claim in it is true**."

## What should happen

The Update Log entry's fenced block must be byte-identical to
`/tmp/e2e-05.txt`'s contents at the time the E2E block in § "End-to-end
verification" was run — copy it in directly (`cat /tmp/e2e-05.txt`), not
retyped.

## How to fix

1. Re-run the § "End-to-end verification" block verbatim (it is safe to
   re-run — both mutations are applied and reverted with `sed -i` inside the
   block itself, and the tree is clean).
2. Replace the existing `### Update — 2026-08-08 06:38 (end-to-end
   verification)` fenced block with the exact, unedited contents of the
   resulting `/tmp/e2e-05.txt` (e.g. paste the output of `cat /tmp/e2e-05.txt`
   directly — do not retype any line).
3. Confirm `diff /tmp/e2e-05.txt <new pasted block>` is empty before
   reporting complete again.
