# Bug 1 on phase-02: no end-to-end verification entry for the dispatch

**Severity:** major
**Status:** verified — fixed in round 2 (commit `086dfd2`), confirmed at review 2026-08-08
**Filed:** 2026-08-08

## What's wrong

The phase doc's Update Log contains exactly two entries:

1. `### Update — 2026-08-08 03:25 (started)` — a start marker with no output.
2. `### Update — ts=1786160758798 (complete, server-authored)` — the server's
   bookkeeping tail.

There is **no** `### Update — <date> (end-to-end verification)` entry. The phase
doc's § End-to-end verification required one, named the artifact
(`/tmp/e2e-02.txt`), and stated in as many words that the server-authored
`(complete)` entry does not satisfy the requirement.

Scoped to the Update Log section, all four evidence markers are absent:

```
$ SCOPE() { sed -n '/^## Update Log/,$p' <this phase doc>; }
$ SCOPE | grep -c '(end-to-end verification)'                              → 0
$ SCOPE | grep -c 'e2e-02'                                                 → 0
$ SCOPE | grep -c 'classify_idle_shell_never_awaiting_input ... FAILED'    → 0
$ SCOPE | grep -c 'classify_dead_wins_over_bell_and_command ... FAILED'    → 0
```

The mutation-pair evidence exists only as prose inside the server-authored
completion summary:

> "Both mutation pairs verified: Mutation 1 (`if false`) correctly causes
> `classify_idle_shell_never_awaiting_input` to fail; Mutation 2 (dead check
> removed) correctly causes `classify_dead_wins_over_bell_and_command` to fail.
> All restored and passing."

That is a summary of results, not captured output — one of the four forms
`docs/dev/WORKFLOW.md` § "End-to-end verification" explicitly rejects — and it
sits inside the one entry the spec named as not counting. It is also the exact
shape WORKFLOW.md § "A pasted transcript is a claim, not evidence" lists third:
results asserted in the completion summary while the Update Log carries only a
stub.

**This is the second consecutive phase to bounce on this same requirement**
(phase-01, [bug-01-1](bug-01-1.md)).

## What should happen

`docs/dev/WORKFLOW.md` § "End-to-end verification" requires an Update Log entry
**authored for this dispatch**, containing output captured mechanically
(redirect to a file, paste that file) — not retyped, reconstructed from memory,
or summarised into prose. The phase doc's § End-to-end verification names the
artifact precisely: `/tmp/e2e-02.txt` pasted verbatim, plus the transcript of
**both** directions of **both** mutation pairs — the failing run *and* the
restored passing run for each.

## Root cause

The requirement was satisfied *in substance* and lost *in form*. The executor
did the work — every claim in its summary was independently re-verified at
review and all of it held (see § Verified at review below) — but it recorded
the results by writing prose into the completion summary rather than by
redirecting command output to a file and pasting that file into an entry it
authored. The completion summary is server-authored bookkeeping; content placed
there is not the executor's evidence entry, and the `(started)` entry it did
author carries no command output at all.

**A contributing cause is architect-side and is fixed in this round's spec.**
Phase-02's § End-to-end verification block was not fully runnable: mutation
pair 2 was written as a prose instruction in the middle of the block —

> `# Mutation pair 2 — apply (delete the dead early-return), run, restore, run.`
> `# Make the edit manually (delete the 3 lines), then:`

— so the block could not be pasted and executed end to end. WORKFLOW.md
requires the architect to "give the commands as a runnable block, never as
prose"; a block containing a manual step in its middle is prose wearing a code
fence. The refreshed block below is fully mechanical: every mutation is applied
and reverted by a command, and the `perl` and `sed` forms were **executed
against this tree at review** before being written here.
