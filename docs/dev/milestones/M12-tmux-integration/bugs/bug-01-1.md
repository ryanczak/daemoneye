# Bug 1 on phase-01: no end-to-end verification entry for the dispatch

**Severity:** major
**Status:** open
**Filed:** 2026-08-08

## What's wrong

The phase doc's Update Log contains exactly two entries:

1. `### Update — 2026-08-08 02:14 (started)` — a start marker.
2. `### Update — ts=1786156899902 (complete, server-authored)` — the server's
   bookkeeping tail.

There is **no** `### Update — <date> (end-to-end verification)` entry. The phase
doc's § End-to-end verification required one, gave the exact shell block to run
(`/tmp/e2e-01.txt`), and stated in as many words that the server-authored
`(complete)` entry does not satisfy the requirement.

The mutation-pair evidence exists only as prose inside the server-authored
completion summary:

> "Both mutation pairs verified: removing the `session_name == home` filter
> from `pane_map_summary` causes `pane_map_excludes_foreign_session_panes` to
> FAIL; removing the `live.is_empty()` guard from `evict_missing` causes
> `evict_missing_ignores_empty_snapshot` to FAIL. Both restored and passing."

That is a summary of results, not captured output — one of the four forms
`docs/dev/WORKFLOW.md` § "End-to-end verification" explicitly rejects — and it
sits inside the one entry the spec named as not counting.

## What should happen

`docs/dev/WORKFLOW.md` § "End-to-end verification" requires an Update Log entry
**authored for this dispatch**, containing output captured mechanically
(redirect to a file, paste that file), not retyped, reconstructed, or
summarised into prose. The phase doc's § End-to-end verification names the
artifact precisely: `/tmp/e2e-01.txt` pasted verbatim, plus the transcript of
**both** directions of **both** mutation pairs — the failing run *and* the
restored passing run for each.

## Root cause

The requirement was satisfied *in substance* and lost *in form*. The executor
did run the work — every claim in its summary was independently re-verified at
review and all of it held (see § Verified at review below) — but it recorded
the results by writing prose into the completion summary rather than by
redirecting command output to a file and pasting that file into its own entry.
The completion summary is server-authored bookkeeping; content placed there is
not the executor's evidence entry, and the `(started)` entry it did author
carries no output at all.
