# Bug 2 on phase-04: round-2 end-to-end entry is a hand-paraphrased summary, not a raw paste

**Severity:** major
**Status:** open
**Filed:** 2026-08-08

## What's wrong

The round-2 Update Log entry (`### Update — 2026-08-08 05:58 (end-to-end
verification)`) is not the pasted contents of `/tmp/e2e-04-r2.txt`. The block
specced in § "End-to-end verification" § "ROUND 2 block" redirects every
command's full output into `$OUT` with `>> $OUT 2>&1`, so the raw file is
2,555 lines — the `cargo test` run alone prints all 1,173 individual `test …
… ok` lines plus per-binary `Compiling`/`Finished`/`Running` headers.

The pasted entry is 23 lines and every line is a hand-written annotation of
what the command showed, not the command's output:

```
test exit=0 (1173 passed; 0 failed)
```

`/tmp/e2e-04-r2.txt` (still present on disk, confirmed at review) contains no
line resembling this — the raw file has `fmt exit=0` / `build exit=0` /
`clippy exit=0` on their own lines (each preceded by real `Compiling`/
`Finished` output), then a `running 1173 tests` block, one `ok` per test, and
finally `test result: ok. 1173 passed; 0 failed; …`. There is no line in the
raw output that reads `test exit=0 (1173 passed; 0 failed)`. Likewise:

```
M3 exit=101 (find_in_panes_results_sorted_by_pane_id FAILED as expected)
```

The raw file's M3-apply section (confirmed at review, lines 1323–1359) has
`M3 exit=101` on its own line, with the `FAILED` line and the panic message
printed separately, several lines above it, by `cargo test`'s own output —
not appended as a parenthetical on the same line.

This is exactly the first of the three shapes named in
`docs/dev/WORKFLOW.md` § "A pasted transcript is a claim, not evidence":
"**Paraphrase in place of a quote.** The Update Log describes what the
command showed instead of showing it." That section states explicitly: "A
true claim in a hand-made transcript is still a failure… What was missing
was the evidence chain, which is the only part that survives to the next
reader."

Independently re-running the ROUND 2 block's substance at review (fmt/build/
clippy/test gates, mutation M3 both directions, `git diff --stat` scope)
confirmed every claim in the pasted entry is true — 1173 passed, both sorts
present, foreign sort precedes `take`, M3 fails mutated and passes restored,
tree clean afterward. **The code and the claims are not in question — the
evidence artifact is.**

## What should happen

Per `docs/dev/STANDARDS.md` § 1 and `docs/dev/WORKFLOW.md` § "End-to-end
verification": "**Capture mechanically, never by hand.** Redirect each
command's output to a file and paste that file's contents." The Update Log
entry headed `### Update — <date> (end-to-end verification)` must contain the
verbatim contents of `/tmp/e2e-04-r2.txt` — the actual `Compiling`/`Finished`
lines, the full `running 1173 tests` block, every `test … ok` line, and the
real multi-line panic output from the M3-mutated run — not a line-count-
reduced summary of what those sections say.

## How to fix

`/tmp/e2e-04-r2.txt` already exists and is correct (verified at review — it
matches a fresh independent re-run of the same block). No command needs to be
re-run and no source file changes. Replace the existing round-2 end-to-end
Update Log entry's fenced block with the literal contents of
`/tmp/e2e-04-r2.txt` (`cat /tmp/e2e-04-r2.txt`), pasted in full — do not
truncate, summarize, or annotate any line. If the file has been removed by the
time this is fixed, regenerate it by re-running the ROUND 2 block from
§ "End-to-end verification" verbatim and unmodified, then paste that file's
contents instead.
