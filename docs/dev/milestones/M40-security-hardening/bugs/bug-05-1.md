# Bug 1 on phase-05: the prompt-name test passes without the fix

**Severity:** major
**Status:** open
**Filed:** 2026-11-26

## What's wrong

`load_named_prompt_ignores_a_traversing_name` (`src/config/tests.rs`)
writes `evil.toml` into `prompts_dir()`, which is `etc/prompts/`. It then
calls `load_named_prompt("../evil")`. That name resolves to
`etc/prompts/../evil.toml`, which is `etc/evil.toml`, a file the test
never writes. So the old code finds no file and returns the builtin prompt
too, and the test passes either way.

The reviewer checked it with a mutation: `validate_path_name` was made to
return `Ok` for every name. Five of the six refusal tests then failed, but
this one still reported `1 passed`.

The phase asked for the file to be planted at `etc/evil.toml` and for a red
run. No red run was pasted for it.

## What should happen

The test plants a valid prompt file (system text `EVIL`) at the place the
traversing name actually points: `prompts_dir().parent()`, joined with
`evil.toml`. Then it asserts that `load_named_prompt("../evil")` does not
return `EVIL`. Without the validator, the old code reads that file, so the
test is red.

## Root cause

The test planted the fixture beside the prompts, not at the path the
traversing name resolves to.

## Definition of done

- [ ] `load_named_prompt_ignores_a_traversing_name` passes on the fixed
      code.
- [ ] With `validate_path_name` mutated to always return `Ok`, it
      **fails**. Paste that run as output, then restore. It passes under
      the mutation today.
