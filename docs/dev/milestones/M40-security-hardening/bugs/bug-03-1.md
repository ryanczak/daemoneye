# Bug 1 on phase-03: remote edit/create failures no longer name their cause

**Severity:** minor
**Status:** closed (2026-11-25, architect takeover; see the phase's review verdict)
**Filed:** 2026-11-25

## What's wrong

A remote edit or create whose temp file cannot be created reports **no
result line**, in either interpreter branch. The reviewer ran
`build_remote_edit_cmd` against a file in a 0555 directory, under the
narrowed-`PATH` harness. `remote_write_outcome` returned `None` for both
`python3` and `perl`.

On `None`, the plain path reports its generic "unclear" message. The sudo
edit is worse: it says *"the password was not accepted or sudo refused
it"*, which is wrong.

**This is a regression in the Perl branch.** Before this phase, its
`open(… '>', $t) or do{print "DE_ERROR: $!" …}` printed
`DE_ERROR: Permission denied`. Three causes:

1. **Perl's `tempfile(…)` croaks rather than returning false**, so its
   `or do{print "DE_ERROR…"}` never runs. The whole payload runs inside
   the wire command's `perl -e 'eval(pack(…))'`. That outer `eval`
   swallows the croak, and nothing is printed.
2. **Perl's failure line, `"DE_ERROR: ${$e||'edit failed'}"`, prints an
   empty reason.** The same line is in the create payload. `${ … }`
   inside a double-quoted string is a scalar *dereference*, so the error
   text is lost. Measured: with `$e = "boom"` it prints `DE_ERROR: `.
3. **Python** (`write.rs` `remote_edit_payload_hex`,
   `ops.rs` `build_remote_create_cmd`):
   - `tempfile.mkstemp(…)` runs before the `try:`, so its exception is an
     uncaught traceback with no `DE_ERROR:` line. The create payload's
     `os.makedirs` is the same.
   - Inside the `try`, `except BaseException:` prints a fixed
     `DE_ERROR: edit failed` / `create failed` without the exception text.

## What should happen

Any failure of a remote edit or create payload, in both branches, prints
one line `DE_ERROR: <reason>`, with a reason that is non-empty and names
the cause, such as the OS error text. This holds from the first step that
can fail after the payload's own checks, temp creation included. The
temp is still unlinked whenever it exists. Exit status and the
`__DE_DONE__` trailer are unchanged.

## Root cause

The phase moved temp creation into a library call that signals failure by
dying or raising, not by returning false. That call sits outside each
payload's error handler. The Perl handler's message also uses `${…}`, a
dereference rather than interpolation.
