# Bug 2 on phase-05: the memory readers' refusals are untested

**Severity:** minor
**Status:** closed (2026-11-26, fixed in `1413e8ca`; see the phase's review verdict)
**Filed:** 2026-11-26

## What's wrong

The phase's **Memory** acceptance item also requires that `read_memory`,
`delete_memory` and `list_memories` with namespace `"../../outside"` each
return `Err`. The code does this: each calls `validate_namespace` first.
But no test checks it. `add_memory_refuses_a_traversing_namespace` covers
`add_memory` only. A later change that drops one of those calls would go
unnoticed.

## What should happen

One test, `memory_readers_refuse_a_traversing_namespace`, in
`src/memory_tests.rs` under a temp `HOME`. It asserts that each of
`read_memory`, `delete_memory` and `list_memories` (the last with
`&["../../outside"]`) returns `Err` for `"../../outside"`.

## Root cause

The item was checked off on `add_memory`'s test alone.

## Definition of done

- [ ] `memory_readers_refuse_a_traversing_namespace` passes. It fails under
      the always-`Ok` mutation of `validate_path_name`.
