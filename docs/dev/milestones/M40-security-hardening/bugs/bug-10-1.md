# Bug 1 on phase-10: two credential copies are still dropped unzeroed

**Severity:** major (S14's whole point; one of the two is a regression from before the phase)
**Status:** closed (2026-11-26, fixed in `9b487f2d`; see the phase's review verdict)
**Filed:** 2026-11-26

## What's wrong

1. **The daemon now leaves the deserialized credential unzeroed.** In
   `credential_round_trip` (`src/daemon/executor/shell_exec_auth.rs:82`):

   ```rust
   let credential = zeroize::Zeroizing::new(credential.as_str().to_string());
   ```

   - **Before the phase:** `Zeroizing::new(credential)` **moved** the
     deserialized `String` in, so that allocation was zeroed on drop.
   - **Now:** it zeroes a fresh **copy**. The deserialized `Credential`'s
     own `String` is dropped as plain memory, with the password still in
     it. The spec required "the daemon reads it into `Zeroizing` as today".
2. **`write_answer` moves the answer out of its `Zeroizing` before
   zeroing.** In `src/shell/client_read.rs`:

   ```rust
   let mut input = zeroize::Zeroizing::new(bytes.to_vec());
   let wire = zeroize::Zeroizing::new(encode(ShellRequest::Input {
       bytes: std::mem::take(&mut *input),
   })?);
   ```

   - `mem::take` moves the `Vec` holding the password into the
     `ShellRequest`, and leaves `input` empty.
   - `encode` takes the request **by value** and drops it, along with the
     password bytes, unzeroed.
   - Zeroizing `input` afterwards wipes an empty `Vec`.
   - The spec required that the `ShellRequest::Input` bytes be zeroized
     after use.

## What should happen

Every heap buffer that holds the credential on the daemon side is zeroed
before it is freed:

- the deserialized `Credential`'s `String`;
- the answer `Vec` in `PromptReply::Send`, which is already done;
- the bytes inside the `ShellRequest::Input` that `write_answer` encodes;
- the encoded wire string, which is already done.

## Root cause

1. A borrow-and-copy (`as_str().to_string()`) replaced a move.
2. A `mem::take` handed the buffer to a by-value consumer.

`encode(frame: impl Serialize)` accepts `&ShellRequest`, because `&T`
implements `Serialize`. So the request can be encoded by reference and its
bytes zeroized afterwards.

## Definition of done

- [ ] `Credential` gives up its `String` by value, for example through an
      `into_inner(self) -> String`. Alternatively, it zeroizes itself on
      drop. `credential_round_trip` moves the credential into `Zeroizing`
      with no copy.
- [ ] This prints **nothing**. Today it prints line 82:
      `grep -n 'Zeroizing::new(credential.as_str' src/daemon/executor/shell_exec_auth.rs`
- [ ] `write_answer` keeps ownership of the `ShellRequest` it encodes, and
      zeroizes that request's `bytes` after encoding.
- [ ] This prints **0**. Today it prints 1:
      `grep -c 'mem::take' src/shell/client_read.rs`
- [ ] `credential_round_trip_returns_a_zeroizing_answer` and every other
      phase-10 test still pass. The lib suite reports **3202**: no new
      test, and a higher count is scope creep.
