# Bug 1 on phase-04: End-to-end verification transcripts are missing from the Update Log

**Severity:** blocker
**Status:** verified
**Filed:** 2026-07-30

## What's wrong

The phase doc's "End-to-end verification" section (`docs/dev/milestones/M6-verification-and-hygiene/phase-04-audit-prompts-command.md:159-174`)
requires three things quoted in the Update Log from a **real run**, each
command's actual stdout redirected to a file and pasted:

1. `daemoneye audit-prompts` against a throwaway `HOME` seeded from current
   assets — full report + `echo $?` showing `0`.
2. The same against a tree with one installed literal edited to a superseded
   path — full report + `echo $?` showing non-zero.
3. The before/after tree listing proving nothing was written.

The section is explicit that this has already bounced twice on phase 03 for
exactly this failure class — "once for paraphrasing instead of quoting, once
for a transcript in which 24 of 25 lines were real and one was spliced in" —
and instructs: "Redirect each command's output to a file and paste that
file's contents. Do not reconstruct a transcript by hand."

The completion Update Log entry (`### Update — ts=1785435336697 (complete,
server-authored)`, phase doc lines 241-380) contains no transcript section at
all. The only content under the "End-to-end verification" heading in that
entry is one prose sentence:

> **End-to-end verification:** Clean seeded tree exits 0 (42 literals, all
> current). Injected `var/log/events.jsonl` into the prompt → exits 1 with 1
> superseded finding. Before/after tree diff proves zero files written.

This is an assertion, not a transcript — no pasted command output, no `echo
$?` line, no directory listing. Grepping the whole Update Log
(`grep -n "echo \$?"` and `grep -n "\$ daemoneye"`) over the phase doc
returns nothing. This is the **third** occurrence of this exact defect class
on this milestone (bug-03-1: paraphrase instead of quote; bug-03-2: a
spliced/reconstructed transcript).

STANDARDS.md § 1 DoD is explicit: "the actual output is quoted in the
completion Update Log entry under 'End-to-end verification.' A green `cargo
test` run that exercises a temp-directory-scoped fake is **not** by itself
sufficient."

Independent verification during review (not part of this bug, informational
only): the review reproduced all three scenarios against a real throwaway
`HOME` with the shipped binary and the executor's *numbers* were accurate
(42 literals/0 findings on the clean tree, exit 0; 43 literals/1 superseded
finding after injecting `var/log/events.jsonl`, exit 1; an isolated
before/after snapshot of the audit run itself was byte-identical). The
underlying behavior works. The defect is procedural: the phase doc's DoD
requirement for quoted, redirected transcripts in the Update Log was not
met, and given the repeat-occurrence pattern this milestone treats that
requirement as load-bearing on its own, not just a proxy for "does it work."

## What should happen

The Update Log's completion entry must contain the three transcripts,
each produced by redirecting a real command's output to a file and pasting
that file's contents verbatim — not reconstructed, not paraphrased, not
copied from this bug report or any other document.

## How to fix

1. Seed a throwaway `HOME` (e.g. via `crate::test_home_guard()`-style setup
   or a plain `HOME=/tmp/... daemoneye setup` shell sequence) with the
   current assets.
2. Run `HOME=$T daemoneye audit-prompts > /tmp/run1.txt 2>&1; echo $? >>
   /tmp/run1.txt`, then paste `/tmp/run1.txt`'s contents into the Update Log.
3. Edit one installed literal in `$T/.daemoneye/etc/prompts/sre.toml` to a
   superseded path (e.g. append a line referencing `` `var/log/events.jsonl` ``),
   repeat the redirect-and-paste for run 2.
4. Snapshot the tree (`find $T/.daemoneye -type f -exec md5sum {} \; -exec
   stat -c '%Y %n' {} \;`) immediately before and immediately after the
   audit-prompts invocation (not spanning the injection edit, which is not
   part of the command under test), diff them, and paste both the snapshot
   command output and the diff (empty) into the Update Log.
