# Bug 4 on phase-01: hardcoded session name, and a `config.toml` write that is immediately discarded

**Severity:** minor
**Status:** open
**Filed:** 2026-07-30

## What's wrong

Two small defects in the harness. Neither breaks the green suite; the first
blocks the bug-01-2 mutation from reaching any assertion.

**1. All three tests hardcode the session name `de-test`.**
`tests/isolation.rs:69`, `:105`, `:137` each call `env.start_daemon("de-test")`.
While isolation holds, each test has its own tmux server and the collision is
invisible. The moment isolation is broken — which is exactly what the required
mutation does — the three tests share one server and collide:

```
daemoneye: daemon failed to start: Failed to create tmux session 'de-test':
           duplicate session: de-test
```

So the harness masks the very failure the mutation is supposed to expose,
converting a meaningful assertion failure into a startup panic (see bug-01-2).

**2. `IsolatedEnv::new()` writes a `config.toml` that is then thrown away.**
The constructor (`tests/harness/mod.rs:33-49`) creates `.daemoneye/etc/` and
writes a config, and `start_daemon` then calls `write_test_config()`
(`:158-177`) which writes a byte-identical config to the same path. The
executor's Update Log explains why the second write is needed — `daemoneye
setup`'s `ensure_dirs()` overwrites any pre-existing `config.toml` with the
bundled default — which is a good finding, and it makes the **first** write dead.
The duplicated 12-line TOML literal is now in two places and will drift.

## What should happen

1. Each test uses a distinct session name, so tests remain independent even when
   sharing a server. This is what lets the bug-01-2 mutation produce a
   meaningful per-test result.
2. The config TOML exists in exactly one place, written at the point where it
   survives.

## How to fix

In `tests/isolation.rs`: give each test its own session name (`de-test-boot`,
`de-test-hooks`, `de-test-default`, or take the name as a parameter). Any scheme
works as long as no two tests can request the same name.

In `tests/harness/mod.rs`: delete the `config.toml` write from `new()`, keeping
only `write_test_config()` called from `start_daemon`. Keep the
`create_dir_all` of `.daemoneye/etc/` wherever it is still needed. Keep the
socket-path length assertion in `new()` — that one is load-bearing and must stay
at construction. Retain the comment explaining that `setup` overwrites
`config.toml`, since it is the reason for the ordering.

While here: the dummy key is written as `sk-ant-test0000…`. Change the literal so
it does not begin with a real provider key prefix — a repo-wide secret scan
should not have to reason about whether it is live. Any obviously-inert value
(`test-key-not-a-real-credential`) is fine; the daemon does not validate it at
boot.
