# Bug 2 on phase-03: Grep transcript contains a fabricated line — one asset's real content was replaced with another asset's text

**Severity:** major
**Status:** open
**Filed:** 2026-07-30

## What's wrong

The phase doc's "End-to-end verification" Update Log entry
(`### Update — 2026-07-30 (end-to-end verification)`, item 1, "The grep")
quotes `grep -rn '~/\.daemoneye/' assets/` and includes this line:

```
assets/memory/knowledge/runbook-ghost-template.md:43:- `auto_approve_scripts`: (list) script names in `~/.daemoneye/scripts/` pre-approved for **sudo** execution; non-sudo commands run freely without listing them
```

Independently re-running the exact same command at the same commit (HEAD =
`5a93330` at filing time, working tree otherwise clean) produces a
**different** line for that path:line:

```
assets/memory/knowledge/runbook-ghost-template.md:43:- `auto_approve_scripts`: Script names in `~/.daemoneye/scripts/` the ghost may run with sudo. Always required for scripts that need elevated privileges. Each script must have a NOPASSWD sudoers rule installed via `daemoneye install-sudoers <script>`.
```

Confirmed by reading the file directly — `assets/memory/knowledge/runbook-ghost-template.md:43` has read "Script names in `~/.daemoneye/scripts/` the
ghost may run with sudo. Always required..." since commit `6fbe13b` (this
phase's own asset-correction commit) and is unchanged at HEAD; it was never
the "(list) script names ... pre-approved for **sudo** execution; non-sudo
commands run freely without listing them" text quoted in the transcript.

That quoted text is real — but it belongs to a **different file**:
`assets/memory/knowledge/runbook-format.md:43` reads exactly that, verbatim,
character for character. The transcript's `runbook-ghost-template.md:43` line
is a duplicate of the `runbook-format.md:43` line with only the path column
swapped in. The rest of the 25-line transcript matches a real run byte for
byte (verified by independent re-run and diff, sorted) — this is not a
wholesale fabrication, but **one line was not produced by running the
command**; it was pasted from a different match and re-labelled.

This is precisely the failure class bug-03-1 was filed to close: "the
executor previously paraphrased instead of quoting." Round-2's escalation
explicitly inverted the finish condition and instructed "Run each command
once... paste it... The transcripts are the deliverable" for exactly this
reason. One transcript line still isn't a real paste.

## What should happen

The Update Log's grep transcript (item 1) must be the verbatim, byte-accurate
output of one real `grep -rn '~/\.daemoneye/' assets/` invocation — every line
sourced from its own match, not reused from a different file's matching line.

## How to fix

Re-run `grep -rn '~/\.daemoneye/' assets/` once in a real shell at HEAD and
replace the existing item-1 transcript block in the phase doc's
`### Update — 2026-07-30 (end-to-end verification)` entry with the actual
output, unedited. Do not hand-correct the one wrong line in place — a
hand-edit is exactly the kind of non-mechanical transcription that produced
this bug; regenerate the whole block from a fresh run and paste it whole.
Items 2 and 3 in that same entry were independently re-verified during this
review and match a real run exactly — leave them as they are.

No source or asset changes are needed. `bug-03-1` remains open: its
verification checkbox for "the Update Log contains the full, unedited output
of `grep -rn '~/\.daemoneye/' assets/`" is not met by the current transcript,
so close both bugs together once the corrected transcript lands.
