# Bug 2 on phase-04: test-isolation race in `audit_prompts_exits_zero_on_clean_tree`

**Severity:** major
**Status:** verified
**Filed:** 2026-07-30

## What's wrong

`src/cli/commands/audit_prompts.rs:214-234`:

```rust
#[test]
fn audit_prompts_exits_zero_on_clean_tree() {
    let (_tmp, _lock) = setup_test_home();
    // Seed a clean tree
    crate::config::Config::ensure_dirs().unwrap();
    drop(_lock);

    // Run the audit — it should exit 0 (no panic, no non-zero exit)
    // We can't easily capture process::exit in a unit test, so we test
    // the inner logic directly.
    let assets = collect_assets();
    let non_current = print_report(&assets);
    ...
```

`drop(_lock)` releases the `test_home_guard()` mutex **before**
`collect_assets()` runs — and `collect_assets()` reads HOME-dependent paths
(`prompts_dir()`, `config_dir().join("memory").join("knowledge")`, and the
file contents under them). Once the lock is dropped, any other test in the
same binary that also takes `test_home_guard()` (there are dozens across the
crate — every HOME-mutating test does) is free to acquire it and call
`std::env::set_var("HOME", ...)` to point at a different temp directory.
Rust's default test harness runs tests in parallel threads by default, so
this is a real, not theoretical, race: `collect_assets()` can read a
different tree than the one this test just seeded, either finding files that
don't match its later assertions or racing a `HOME` value that no longer
points at `_tmp` (which remains alive only because `_tmp` — the `TempDir` —
is still in scope, but the code under test is no longer guaranteed to be
reading it).

This is precisely the class of bug M6 phase 01 (test-isolation-harness) and
the `test_home_guard()` accessor exist to prevent: the guard is supposed to
serialize *all* HOME-dependent work for the lifetime of the test, not just
the setup step.

The other three tests in the same file (`audit_prompts_reports_superseded_path`,
`audit_prompts_no_write_property`, `audit_prompts_missing_prompt_no_panic`)
correctly hold `_lock` for the full duration of their HOME-dependent work
and `drop(_lock)` only at the end, right before the test returns. This one
test is the outlier.

`setup_test_home()`'s contract (`audit_prompts.rs:205-212`) returns the
guard to the caller precisely so the caller controls its lifetime — the
helper does not scope it internally. The `TempDir` (`_tmp`) does outlive the
HOME-dependent work in every test, including this one; the defect is
specifically the premature `drop(_lock)`, not a `TempDir` lifetime issue.

## What should happen

`_lock` must be held for the entire duration that this test's code depends
on `HOME` pointing at its own throwaway directory — i.e., through
`collect_assets()` and `print_report()`, matching the pattern in the other
three tests in the file.

## How to fix

In `src/cli/commands/audit_prompts.rs`, move the `drop(_lock)` call in
`audit_prompts_exits_zero_on_clean_tree` to the end of the test function,
after the `assert!` calls that inspect `prompt`, matching the idiom used in
the other three tests (`audit_prompts_reports_superseded_path`,
`audit_prompts_no_write_property`, `audit_prompts_missing_prompt_no_panic`).
