# Bug 1 on phase-05: Missing mechanically-captured E2E transcripts in the Update Log

**Severity:** blocker
**Status:** closed — fixed
**Filed:** 2026-07-30
**Closed:** 2026-07-30 (round 2, approved_after_1 — see phase doc's Review verdict)

## What's wrong

The phase doc's End-to-end verification section (`docs/dev/milestones/M6-verification-and-hygiene/phase-05-severity-gate-honesty.md`
§ "End-to-end verification") requires three pasted, mechanically-captured
artifacts:

1. The redirected output of
   `HOME=$H cargo test --test integration <below_threshold_test> -- --nocapture > /tmp/e2e-gate.txt 2>&1; echo "exit=$?" >> /tmp/e2e-gate.txt`,
   pasted from the file.
2. The matching `webhook_discarded` line from the event segment the test
   wrote.
3. For the no-severity (absence) case, the grep's exit status
   (`echo "grep-exit=$?"`) proving the absence is observed, not merely
   unsearched.

None of these appear in the Update Log. The log contains only a
"(started)" stub (`### Update — 2026-07-30 19:52 (started)`) and the
server-authored "(complete)" entry
(`### Update — ts=1785441753126 (complete, server-authored)`), whose
"Command output tails" section is the standard `cargo fmt`/`build`/
`clippy`/`test` gate output — not the phase-specific E2E artifact the spec
required. The only occurrences of `e2e-gate` / `grep-exit` in the phase doc
are in the architect's own spec text at lines 223-229; there are none in the
Update Log.

This is despite the underlying work being real: a grep of the raw session
log (`.rexymcp/sessions/session-phase-05-6a6baae2.jsonl`) found 19 hits of
`e2e-gate` and 4 of `grep-exit`, confirming the executor ran the prescribed
commands. It simply never pasted the output into the Update Log — the
evidence chain was not carried through to the artifact that survives review,
per `STANDARDS.md` §1's mechanical-capture box and `WORKFLOW.md`
§ "A pasted transcript is a claim, not evidence" ("Results asserted in the
completion summary while the Update Log has only a '(started)' stub" is
listed there as one of the three observed failure shapes — this is that
shape).

This is the 5th occurrence of this defect class on M6 (bug-03-1, bug-03-2,
bug-04-1, bug-04-4, now this one).

## What should happen

The phase's Update Log completion entry must contain, pasted verbatim from
the actual command output files (not retyped, paraphrased, or summarized):

- The full (or representatively tailed) contents of `/tmp/e2e-gate.txt`
  (or an equivalently named file), including the `exit=$?` line.
- The matching `webhook_discarded` JSONL line pulled from the event segment
  the below-threshold test wrote.
- The absence-proof block for the no-severity case, including a
  `grep-exit=$?` line demonstrating the grep ran and found nothing (rather
  than an empty block that could equally mean "never run").

## How to fix

Re-run the three commands from the phase doc's "End-to-end verification"
section against the current tree (the code itself is correct and does not
need to change — see the phase's Review verdict for the substantive
findings), redirecting each command's output to a file, and paste the file
contents into a new Update Log entry on
`docs/dev/milestones/M6-verification-and-hygiene/phase-05-severity-gate-honesty.md`.
Do not hand-assemble or retype the transcript — capture mechanically per
`STANDARDS.md` §1 and `WORKFLOW.md` § "End-to-end verification".
