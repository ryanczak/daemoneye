# Bug 1 on phase-03: Update Log omits the three required real-run quotes

**Severity:** major
**Status:** verified
**Filed:** 2026-07-30

## What's wrong

The phase doc's "End-to-end verification" section (phase-03-fix-stale-prompt-paths.md,
§ "End-to-end verification") is explicit:

> Quote in the Update Log, from a real run:
> 1. `grep -rn '~/\.daemoneye/' assets/` — the full output, showing every surviving
>    occurrence is a correct path.
> 2. The assets-clean test passing with an empty quarantine.
> 3. The mutation check from task 4: the broken-`normalise()` run showing the
>    synthetic-corpus test failing, then green after revert.

`STANDARDS.md` § 1 DoD makes this a hard requirement, not a nice-to-have: "the
actual output is quoted in the completion Update Log entry under 'End-to-end
verification.' A green `cargo test` run that exercises a temp-directory-scoped
fake is **not** by itself sufficient."

The phase doc's own Update Log (lines 218–351) has exactly two entries: a
"started" stub and a terminal "complete, server-authored" entry. The latter's
**Summary** paraphrases the three required results in prose —

> `grep -rn '~/\.daemoneye/' assets/` shows only correct paths remain — all
> `~/.daemoneye/var/`, `~/.daemoneye/scripts/`, `~/.daemoneye/etc/`, and bare
> root references are legitimate.
>
> Mutation check confirmed: replacing `normalise()` to return `None`
> unconditionally causes the synthetic-corpus test to fail with `expected 7
> findings, got 0`.

— but none of the three items is quoted as actual terminal output. The full
`grep` output is not present anywhere in the doc. The assets-clean test's pass
line (`test config::path_audit::tests::all_assets_audit_clean_with_empty_quarantine
... ok`) is not isolated/quoted — the "Command output tails" block is a generic
`cargo test` tail that happens to end on unrelated tests
(`session_store::tests::*`, `memory::tests::update_memory_sets_updated_timestamp`)
and never shows `path_audit` tests running at all. The mutation-check run
(broken `normalise()` → failing test → revert → green) is not shown as a real
terminal transcript anywhere; the "expected 7 findings, got 0" string in the
Summary is a paraphrase of the actual assertion message
(`"expected 7 findings from historical corpus, got 0"`, per
`src/config/path_audit.rs`'s `extractor_detects_historical_stale_literals`),
not a copy of it.

This is not merely a formatting gap — the sibling phase, phase-02, met this
exact same requirement correctly: its Update Log has explicit intermediate
entries ("16:15 (red run — task 5 step 2)", "16:20 (green run — task 5 step
4)") quoting the real, unquarantined audit findings verbatim and the real
green test-run summary. Phase-03 had the same obligation and did not produce
the equivalent artifact.

## What should happen

The Update Log must contain, quoted verbatim from an actual terminal run:

1. The full output of `grep -rn '~/\.daemoneye/' assets/` (every surviving
   line).
2. A test run isolating (or clearly showing) `all_assets_audit_clean_with_empty_quarantine`
   passing.
3. A transcript of the mutation check: `normalise()` mutated to return `None`
   unconditionally, `cargo test --lib config::path_audit` run, showing
   `extractor_detects_historical_stale_literals` (and any other tests that
   incidentally fail as a result — there are others, since `normalise` is
   shared) FAILING, followed by `git checkout --` and a clean green re-run.

Note for the reviewer redoing this independently (already done as part of
this review): all three claims in the existing prose Summary are in fact
**true** — the grep output is clean, the assets-clean test passes, and the
mutation check does cause `extractor_detects_historical_stale_literals` to
fail (along with three other `normalise()`-dependent tests, which is expected
since the mutation is global to the function, not scoped to the one test).
This bug is about the missing artifact in the Update Log, not about
incorrect underlying work — no code or asset changes are required to fix it.

## How to fix

Append a new Update Log entry (or amend the existing "complete" entry) to
`docs/dev/milestones/M6-verification-and-hygiene/phase-03-fix-stale-prompt-paths.md`
containing the three quoted transcripts described above, taken from a real
run in the repo at HEAD. No source or asset changes are needed — this is a
documentation-completeness fix only.

## Resolution — 2026-07-30 (architect takeover)

Closed by the architect during the phase-03 session takeover (see the phase
doc's "Update — 2026-07-30 (architect takeover)" entry).

The grep block in the Update Log was regenerated **programmatically** from a live
`grep -rn '~/\.daemoneye/' assets/` run rather than transcribed by hand — the
failure mode in both bugs was transcription, so hand-copying would have carried
the same risk. Verified afterwards that every line of the real command output
appears verbatim in the block (0 missing), and that
`runbook-ghost-template.md:43` now carries its real text rather than
`runbook-format.md:43`'s.

Transcripts 2 (assets-clean run) and 3 (mutation check) were independently
confirmed byte-identical to live re-runs by the round-2 review and were left
untouched.

All four gates re-run by the architect: fmt/build/clippy exit 0; `cargo test`
955 lib + 27 integration (2 ignored) + 3 isolation, zero failures.
