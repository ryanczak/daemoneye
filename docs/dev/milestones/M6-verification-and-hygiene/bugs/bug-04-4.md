# Bug 4 on phase-04: Transcript 3 (no-write proof) is a hand-typed assertion, not a captured diff

**Severity:** blocker
**Status:** verified
**Filed:** 2026-07-30

## What's wrong

The phase doc's re-dispatch note (bug-04-1 fix instructions,
`phase-04-audit-prompts-command.md:296-300`) required:

> 3. **No-write proof** — a recursive listing with mtimes of the throwaway
>    `~/.daemoneye/` taken immediately before and immediately after the
>    `audit-prompts` invocation, plus the diff between them (expected: empty).

What was pasted into the completion Update Log
(`phase-04-audit-prompts-command.md`, "3. No-write proof" under the
`### Update — 2026-07-30 19:14 (complete)` entry) is, in full:

```
DIFF:
(empty - no changes)
```

There is no before-listing, no after-listing, and no `find`/`ls`/`stat`
output — only a terse parenthetical. This is doubly wrong:

1. It omits the two listings the phase doc explicitly asked for (`before`
   and `after`), leaving nothing for a reviewer to diff against.
2. `(empty - no changes)` is not producible by any real `diff` invocation.
   `diff a b` on two byte-identical listings prints **nothing at all** —
   zero bytes to stdout, exit code 0. The string `"(empty - no changes)"` is
   prose describing a diff's result, not a diff's output. A mechanical
   redirect-and-paste of a real `diff` command run against two identical
   files cannot produce this text; someone typed it.

Independent verification during this review (round 2): re-ran the full
sequence live — `daemoneye setup` into a fresh throwaway `HOME`, a real
recursive `find … -exec stat -c '%Y %n' {} \;` listing taken immediately
before `daemoneye audit-prompts` and again immediately after, and a real
`diff` of the two listing files. The listings were 35 entries each, and the
`diff` genuinely produced zero output (confirmed via `echo $?` = 0 and an
empty diff file). **The underlying claim (no write occurred) is true** — this
matches the prior round's independent mutation-tested confirmation. The
defect is procedural, not behavioral: this is the exact failure shape
`STANDARDS.md` §1's new box and `WORKFLOW.md` § "A pasted transcript is a
claim, not evidence" were folded to catch — "a true claim in a hand-made
transcript is still a failure" — and it is the **fourth** occurrence of the
E2E-transcript-omission defect class on this milestone (bug-03-1, bug-03-2,
bug-04-1, now this), the third occurrence of it specifically on phase 04
after bug-04-1 was supposedly closed by this same dispatch round.

Transcripts 1 and 2 in the same completion entry were checked against this
concern too (re-run independently, output diffed line-by-line against what
was pasted) and matched the executor's numbers and structure. Only
transcript 3 is at issue.

## What should happen

The Update Log's completion entry must contain, for the no-write proof: the
actual before-listing file contents, the actual after-listing file contents
(or clear evidence both were captured), and the actual (real, possibly
empty-bodied) output of the diff command — pasted from redirected command
output, not summarized.

## How to fix

1. Seed a throwaway `HOME` via `daemoneye setup`.
2. Immediately before invoking `audit-prompts`, run something like:
   `find "$T/.daemoneye" -exec stat -c '%Y %n' {} \; | sort > /tmp/before.txt`
3. Run `HOME=$T daemoneye audit-prompts > /tmp/run.txt 2>&1`.
4. Immediately after, run the same listing command to `/tmp/after.txt`.
5. Run `diff /tmp/before.txt /tmp/after.txt > /tmp/diff.txt; echo "diff exit=$?" >> /tmp/diff.txt`.
6. Paste the contents of `/tmp/before.txt`, `/tmp/after.txt`, and
   `/tmp/diff.txt` into the Update Log verbatim (or at minimum `before.txt`,
   `after.txt`, and the literal — possibly zero-byte — `diff` output plus its
   exit code). Do not describe the diff result in prose in place of pasting
   it.
