# M36 findings ledger

The 2026-11-01 codebase audit (four read-only passes: executor and shell;
daemon server, IPC, webhook, scheduler and ghost; AI backends, stream,
memory and config; the CLI client), triaged at scoping. Same columns and
triage values as the M31 and M32 ledgers: `act: <phase>`, `defer: <why>`,
`reject: <why>`; a phase that lands a fix rewrites its row's cell to
`fixed: M36 phase-NN, <test name>`.

Severity is the auditor's; the architect re-read every `critical` and
`major` row's code path before triage. Rows the executor adds while fixing
go at the bottom with `Phase` set to the phase that saw them.

## Clean by inspection

Reported clean by the auditors, so no phase touches them for the audit's
sake: the shell-host socket (0700, peer identity on every connection);
`wrap_command` and the marker parsing; the hex-encoded remote payloads and
`sq_escape`; sbx argv building; sudoers install (O_EXCL 0600 then

the readiness pipe; webhook auth, bind check and per-IP limit; session,
agent and runbook name validation; `take_due` / `mark_done`; the catch-up
brief bounds; context truncation and tool pairing (`repair_tail_head`,
`elide_old_tool_results`); memory key and namespace paths; the tmux
environment allowlist; spend gating; IPC framing (`recv_line`, the
cancel-safe `next_line` readers); ratatui's C0/C1 filtering for drawn
text; `top` and viewer alt-screen guards; the transcript caps.
