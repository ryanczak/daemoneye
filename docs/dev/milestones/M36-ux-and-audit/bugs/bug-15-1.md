# Bug 1 on phase-15: `marker_scan_finds_a_marker_split_at_every_offset` never splits a marker, so the scan overlap is untested

**Severity:** major
**Status:** fixed (7a1c4c97, approved 2026-11-07)
**Filed:** 2026-11-07

## What's wrong

`marker_scan_finds_a_marker_split_at_every_offset`
(`src/shell/client_tests.rs`) starts **one** `run_command_with_prompts` and
then loops over every split offset, sending each variant into the same
stream.

The loop's first iteration is `split == 0`. That branch sends the begin
marker and then the end marker **whole**, so the one command finishes on
that iteration. Every later iteration, which holds all the real splits,
sends frames to a connection nothing reads any more. The test asserts only
the single outcome's exit code.

The reviewer set the scan overlap to zero in `read_to_marker`, replacing
`end_marker(nonce).len().saturating_sub(1)` with `0`. With that change, a
marker split across two chunks can never be found. The test still passes:

```
== mutation B: scan overlap 0
test shell::client::tests::streaming::marker_scan_finds_a_marker_split_at_every_offset ... ok
test result: ok. 1 passed; 0 failed; 0 ignored; 0 measured; 2682 filtered out; finished in 0.01s
```

The executor's own mutation check found the same result and attributed it
to "a shadowed binding". That attribution is wrong: the test is vacuous.

## What should happen

Behaviour item 1 of the phase says a marker split across chunks is still
found, because each chunk is scanned with an overlap of one marker length
less one byte. Spec step 1 names this test as the guard for exactly that
case, and Spec step 3's mutation check, overlap set to zero, must turn it
red.

## Root cause

The test exercises one command, not one command per split offset, and its
first iteration is the unsplit case. No split end marker ever reaches a
live reader.

## Definition of done

- [x] `marker_scan_finds_a_marker_split_at_every_offset` runs one complete
      command per split offset strictly inside the end-marker frame. For each
      offset, it sends the begin marker, then the end marker as two chunks
      split at that offset, and asserts that this command's outcome carries
      the real exit code. Each command's `Input` must be recovered fresh:
      call `host.backend.clear_writes()` between commands, or a later command
      recovers an earlier one's nonce.
- [x] **Mutation check, pasted as real output:** with the overlap in
      `read_to_marker` set to `0`, the test **fails**. Restore the overlap,
      and the test passes. Run this against the current tree before the fix
      too: today the mutated run **passes**, which is this bug.
- [x] Production code is unchanged: `src/shell/client.rs` has no diff.
      Only `src/shell/client_tests.rs` changes.
- [x] The full `cargo test` line reads `failed=0`, and the test count stays
      **2762**. The test is rewritten, not added.
