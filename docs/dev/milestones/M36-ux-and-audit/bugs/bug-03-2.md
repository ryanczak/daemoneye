# Bug 2 on phase-03: `HELP_TEXT` names no form, and two `/approvals` replies misquote

**Severity:** minor
**Status:** fixed (65b6d1e9, approved 2026-11-02)
**Filed:** 2026-11-02

## What's wrong

1. Acceptance criterion 4 reads "`HELP_TEXT`, README and
   `docs/REQUIREMENTS.md` FR-1.2.19 name the eight categories and the
   `all` / `host` / `revoke <category>` forms". README and FR-1.2.19 do;
   `HELP_TEXT` (`src/cli/commands/chat.rs:64`) now reads
   `/approvals categories on/off`, which names neither a category nor a
   form — `grep -n revoke src/cli/commands/chat.rs` prints nothing. The
   old row at least named `list/on/off/revoke`.
2. `approvals_cmd` (`src/cli/commands/approval.rs:389` and `:427`) builds
   the `off` / `revoke <category>` reply as `now require{} approval` with
   an `s` for every category but `deletes`. Every category name but `sudo`
   is plural, so `/approvals scripts off` replies
   `✓ scripts now requires approval` while bare `/approvals off` replies
   `✓ commands now require approval` for the same state change.
3. The `host` form's refusals prefix the already-`host`-led argument with
   `host ` again (`approval.rs:417` and `:491`): `/approvals host pinky
   sudo` replies `✗ unknown: /approvals host host pinky sudo — …`, and
   bare `/approvals host` replies `… /approvals host host — …`.

Items 2 and 3 were confirmed by running assertions against the current tree
(then reverted): `scripts off` → `Note("✓ scripts now requires approval")`;
`host pinky sudo` → `Error("✗ unknown: /approvals host host pinky sudo — …")`.

## What should happen

Criterion 4 as written: the `HELP_TEXT` row names the forms
(`<category>|all on|off`, `host <name> [sudo] on|off`, `revoke
[category]`); the table already uses a second line for a command's detail
(`/tail`, `/logs`, `/log`). The `off` / `revoke <category>` replies agree
in number with the category name — `sudo` is the only singular — and a
refusal quotes the user's argument exactly once.

## Root cause

1. The help row was shortened to fit the column instead of using the
   table's detail-line convention.
2. The plural exception is inverted: it treats `deletes` as the only plural
   category when `sudo` is the only singular one.
3. `unknown_category` receives `host {other}` / `host {original}` where
   `other` and `original` already begin with `host`.
