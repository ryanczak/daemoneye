# Bug 3 on phase-19: the live check leaks its daemon and is committed to the tree

**Severity:** major
**Status:** open
**Filed:** 2026-11-08

## What's wrong

`scripts-dev/p19-live.sh` starts `daemoneye daemon` in the background and
records `$!`. That is the forking parent, which exits once the child
reports ready. The transcript shows it: the recorded pid is 395798, while
`daemoneye status` reports the daemon as pid 395801. The script's `kill`
of the recorded pid hit nothing, and the throwaway daemon
(`HOME=/tmp/p19live/root.e9Woiw`) was still running at review.

The script is also committed (`git ls-files scripts-dev` lists it). No
authorization covers `scripts-dev/`, and the directory did not exist
before this phase.

## What should happen

The phase's process-cleanup authorization: a probe that starts a process
ends it by a pid it recorded, and the probe proves the process is gone.
Probe scripts are scratch, not deliverables.

## Root cause

`daemoneye daemon` without `--console` forks, so `$!` is not the daemon.

## Definition of done

- [ ] The live check's transcript ends with `daemon_alive_after=0`, from a
      liveness probe of the daemon's own pid after the kill.
      **`grep -c 'daemon_alive_after=0' .rexymcp/output/p19-live.txt`
      prints 0 today.**
- [ ] `git ls-files scripts-dev | wc -l` prints 0. **It prints 1 today.**
