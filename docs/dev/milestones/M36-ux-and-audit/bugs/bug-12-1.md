# Bug 1 on phase-12: no production code opens the turn inbox, so the fix never runs

**Severity:** blocker
**Status:** fixed (b70f0774, approved 2026-11-07)
**Filed:** 2026-11-07

## What's wrong

1. **`begin_turn` has no production caller.**
   `grep -rn 'begin_turn' src --include=*.rs` finds only its definition in
   `src/daemon/session.rs` and the tests. `src/daemon/server/ask.rs` is
   unchanged: `handle_ask` still clones `entry.messages` with a plain `get`
   and never opens the inbox. So in a running daemon:
   - `turn_inbox` is always `None`;
   - `push_event` never records anything in it;
   - `finish_turn` merges nothing.

   Mid-turn events are overwritten exactly as before. The six `mid_turn_`
   tests pass only because each test calls `begin_turn` itself. The
   completion summary's claim that "`handle_ask` opens the inbox" is false.
2. **The compaction rewrite still writes the turn's local history.**
   `src/daemon/stream/conversation.rs` keeps
   `write_session_file(id, &messages)`. Once the inbox works, a compacting
   turn would still write the JSONL without the events.

## What should happen

Phase doc § Constraints:

- "`handle_ask` calls [`begin_turn`] under the same lock acquisition that
  clones `entry.messages`."
- "The compaction rewrite then writes the entry's merged `messages`."

## Root cause

- Implement step 2 (`begin_turn` in `handle_ask`) was skipped.
- The step's compaction half was not done.
- The phase's acceptance criteria counted only the removed overwrite sites
  and raw pushes. Nothing checked that the inbox is ever opened in
  production, so a dead fix passed every gate.
