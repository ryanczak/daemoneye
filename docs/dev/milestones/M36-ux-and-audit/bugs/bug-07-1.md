# Bug 1 on phase-07: the sudo prompt sends an empty password on Enter

**Severity:** blocker
**Status:** fixed (5045e266, approved 2026-11-05)
**Filed:** 2026-11-05

## What's wrong

`prompt_credential_ratatui` (`src/cli/commands/stream_prompts.rs`) returns
`cred_real` after its loop. On Enter, `credential_step` returns
`ApprovalStep::Done(std::mem::take(value))`, which moves the typed value out
and leaves `cred_real` empty. The reader matches `ApprovalStep::Done(_) => break`
and drops that text. Every sudo password the user types or pastes then goes to
the daemon as the empty string, so every sudo command fails authentication.
Before this phase the typed password was sent correctly.

The eight `approval_input_*` tests call only the step functions.
`approval_input_credential_paste_is_the_value` asserts `Done("hunter2")` from
`credential_step`, which is true, but nothing checks what the reader returns,
so the suite is green.

## What should happen

Phase doc § Behaviour, Credential: "Enter submits." The string that
`prompt_credential_ratatui` returns is the value the user entered. Ctrl+C or a
bare Escape still returns empty.

## Root cause

The step function and the reader each own the value. The step hands it over in
`Done` and empties its copy, while the reader ignores `Done`'s payload and
returns its own copy, which is now empty.
