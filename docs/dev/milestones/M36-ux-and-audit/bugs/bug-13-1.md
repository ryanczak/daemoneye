# Bug 1 on phase-13: `command_has_sudo` skips quoted text, so `sh -c '…; sudo …'` is no longer sudo, and misses sudo behind wrappers, keywords, assignments and paths

**Severity:** blocker
**Status:** fixed (8ffa1f2d, approved 2026-11-07)
**Filed:** 2026-11-07

## What's wrong

The new `command_has_sudo` (`src/daemon/utils/sudo.rs`) treats a `'…'` or
`"…"` region as argument text and skips it whole. Any `sudo` inside the
quotes is never seen.

The reviewer compared the new detector against the old regex
`(?:^|[;&|])\s*sudo\b`:

| command | old | new |
|---|---|---|
| `sh -c 'id; sudo rm -rf /x'` | true | **false** |
| `bash -c "sudo rm -rf /x"` | false | false |

The first row is a **regression**: the old regex caught it, and the new
detector does not. The second is a miss that the new design should close.

Here is the consequence. `GhostPolicy::is_safe` returns `true` for any
command that `command_has_sudo` calls sudo-free. A ghost can therefore run
`sh -c 'id; sudo rm -rf /x'` auto-approved, which the policy refused before
this phase. This is a security phase that widened what a ghost may run.

## What should happen

PE decision (2026-11-01): sudo is detected in every command position. The
string handed to `sh -c` / `bash -c` is a command, so quoted text must be
scanned, not skipped. Both commands above must count as sudo.

Detecting more is acceptable when it fails closed. So, for example,
`grep 'sudo' /var/log/auth.log` may now count as sudo. These must still
**not** match:

- `grep sudo /var/log/auth.log`
- `echo pseudo`
- `cat /etc/sudoers`
- `visudo -c`

## Also folded in (PE decision, 2026-11-07)

The reviewer's comparison also found command positions that neither the old
regex nor the new detector sees. The PE chose to fold them into this bug
rather than a follow-up. All of the following must count as sudo:

- **After a wrapper command.** Once one of these words is in command
  position, every later word of that simple command (up to the next
  separator) is a command position:
  `env`, `nohup`, `time`, `exec`, `command`, `nice`, `ionice`, `timeout`,
  `stdbuf`, `setsid`, `watch`, `xargs`.
  This fails closed and covers flags and values, for example
  `env -i FOO=1 sudo id`, `nice -n 5 sudo id`, `timeout 10 sudo id` and
  `nohup sudo id`.
- **After a shell keyword in command position.** The keywords are `if`,
  `then`, `else`, `elif`, `do`, `while`, `until`, `{` and `!`. Examples:
  `if true; then sudo id; fi`, `{ sudo id; }` and `! sudo id`.
- **After leading assignments.** A `NAME=value` word in command position
  keeps the position: `FOO=1 sudo id`.
- **By path or escape.** A command word whose basename is `sudo`, after one
  leading `\` is stripped, counts: `/usr/bin/sudo id` and `\sudo id`.

These must still **not** match:

- `grep sudo /var/log/auth.log`
- `echo pseudo`
- `cat /etc/sudoers`
- `visudo -c`
- `echo then sudo`, where `then` is an argument
- `which sudo`
- `man sudo`

## Root cause

The `'\'' | '"'` arm of `command_has_sudo` skips to the closing quote and
sets `at_command = false`. Nothing inside a quote is ever tested.
