# Bug 1 on phase-10: `scrub_transport_error` drops the error's cause; a dead `_url` binding grows `GeminiClient::chat`

**Severity:** major
**Status:** open
**Filed:** 2026-11-06

## What's wrong

1. `src/ai/mod.rs` · `scrub_transport_error` builds its result with
   `anyhow::Error::msg(e.without_url())`. `Error::msg` keeps only the
   top-level Display text and drops the source chain. A refused connection
   used to read
   `error sending request …: client error (Connect): tcp connect error: Connection refused (os error 111)`
   on the stream path (`{:#}`). It now reads only `error sending request`.
   This was reproduced in a scratch crate with reqwest 0.13.5:

   ```
   raw      {:#}: error sending request for url (http://127.0.0.1:1/?key=SECRETKEY123): client error (Connect): tcp connect error: Connection refused (os error 111)
   msg      {:#}: error sending request
   new      {:#}: error sending request: client error (Connect): tcp connect error: Connection refused (os error 111)
   ```

   `secrets_transport_error_drops_url` asserts only that the text is
   non-empty, so it cannot catch this.
2. `src/ai/backends/gemini.rs` · `GeminiClient::chat` keeps
   `let _url = gemini_stream_url(&self.model);`. The value is never used;
   the underscore exists only to silence the unused-variable warning. That
   line is what pushed `chat` from 263 to 264 lines, and the allowlist
   entry was raised to match. The spec said the entry "must not grow".

## What should happen

- Phase doc § Behaviour: "an error built from a `reqwest::Error` never
  includes the request URL. Its message still names what went wrong (for
  example the connection failure)." So the scrubbed `{:#}` text names the
  connection failure, and the URL and key stay out.
- `GeminiClient::chat` holds no dead binding, and its allowlist entry is
  back at 263 or lower.

## Root cause

- `anyhow::Error::msg` stores a Display value, not an `std::error::Error`, so
  `source()` is lost. `anyhow::Error::new` on the `without_url()` error keeps
  the chain. That is the third line of the scratch output above.
- The `url` local was left behind as `_url` when the request moved into
  `gemini_stream_request`.
