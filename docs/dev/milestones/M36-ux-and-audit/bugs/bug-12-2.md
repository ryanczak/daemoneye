# Bug 2 on phase-12: a compacting turn whose entry was evicted mid-turn writes an empty session file

**Severity:** major
**Status:** fixed (ca441b75, approved 2026-11-07)
**Filed:** 2026-11-07

## What's wrong

The compaction rewrite in the `Done` arm of
`src/daemon/stream/conversation.rs` writes the wrong history when the
session's entry is gone at write-back.

- `merged_messages` starts as `Vec::new()`. It is filled only inside
  `if let Some(entry) = store.get_mut(id)`.
- When the entry is gone at write-back, `merged_messages` stays empty.
- On a compacting turn, `write_session_file(id, &merged_messages)` then
  replaces the session's JSONL with an empty file, and the conversation is
  lost.

Before this phase, that path wrote the turn's own `messages`.

The entry can be gone because `cleanup_pass`, run every 60 s from
`startup.rs`, evicts sessions that have been idle for 1800 s and have no
live presence connection. Idle time is measured from `last_accessed`, which
is stamped at turn start. A single turn can run longer than that: a
`wait: true` command can take up to 3600 s. So a long `daemoneye ask` turn
can lose its entry mid-turn.

## What should happen

When the entry is absent at write-back, the compaction rewrite writes the
turn's own `messages`, as before this phase. There is no inbox to merge in
that case. When the entry is present, it writes the merged history, as now.

## Root cause

The `merged_messages` default is an empty vec. It should be the turn's
messages.
