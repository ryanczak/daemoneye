# Bug 2 on phase-03: a 5xx that outlasts its retries is recorded as neutral, so a 5xx outage never trips the breaker

**Severity:** major
**Status:** fixed (`728d9e7e`, architect takeover 2026-11-27)
**Filed:** 2026-11-27

## What's wrong

`src/ai/mod.rs:311-330`, `send_with_retry_inner`. A 429 or 5xx is retried
twice by the second arm, whose guard is `retries < 2`. Once the retries are
spent, the response falls through to the third arm:

```rust
            Ok(resp) => {
                if resp.status().as_u16() == 408 || resp.status().as_u16() == 429 {
                    permit.record_failure();
                } else {
                    permit.record_neutral();
                }
```

So a 500, 502, 503 or 504 that is still failing after the retries is
resolved with `record_neutral`. Since bug-03-1's fix, a neutral outcome
leaves the count unchanged. The result is that an endpoint answering 5xx
forever never trips its breaker. This is the outage case the breaker
exists for.

A half-open probe that gets a 5xx is also resolved neutral. That closes
the breaker (`record_neutral` clears `open_until` for a probe,
`src/ai/circuit.rs:79-87`), when it should re-open for a full cooldown.

This is a regression from 2.12.0. At `57691b5a` every `Err` from
`send_with_retry_inner` counted as a failure, so five 5xx calls opened the
breaker. The defect has been in the tree since the phase's first run,
`8b596c92`. No test covers a 5xx: every request-path test answers with
`200` or `400`.

**Probed 2026-11-27** with a scratch test (in a throwaway worktree at
`5bd3a45b`, since removed). A local server answers
`HTTP/1.1 503 Service Unavailable` to every request. One `send_with_retry`
call is made to it, with the count starting at 0. Output:

```
SCRATCH503 err=true hits=3 count_after=0
test result: ok. 1 passed; 0 failed; 0 ignored; 0 measured; 3228 filtered out; finished in 6.02s
```

`hits=3` shows the two retries ran. `count_after=0` shows nothing was
recorded.

## What should happen

Required behaviour 1 lists "a 5xx" under **Failure**. A 5xx, or a 429,
that is still failing after `send_with_retry`'s own retries resolves the
permit with `record_failure`. A 408 also resolves it with
`record_failure`. Only the other 4xx are neutral. A half-open probe that
ends in a 5xx re-opens the breaker (Required behaviour 3, "Probe fails").

`send_with_retry`'s retry and `Retry-After` behaviour stays unchanged
(Required behaviour 4).

## Root cause

The third arm decides between failure and neutral with an allow-list for
failure (`408 || 429`). It should use an allow-list for neutral: a 4xx
other than 408 and 429. The 5xx statuses are retriable, so they reach this
arm only after their retries run out, and the arm never considered them.
