# Bug 1 on phase-10: the daemon never re-adopts a surviving shell — `scan_shell_ids` rejects real sockets

**Severity:** blocker (fails the PE's hard exit criterion — restart survival)
**Status:** fixed
**Filed:** 2026-09-08 (found by the architect-run live sweep at milestone close)

## What's wrong

`src/shell/registry.rs` `scan_shell_ids` filters directory entries with
`file_type.is_file()`:

```rust
        let Ok(file_type) = entry.file_type() else { continue; };
        if !file_type.is_file() {   // <-- rejects the real socket
            continue;
        }
        let name = entry.file_name();
        let name = name.to_string_lossy();
        let Some(stem) = name.strip_suffix(".sock") else { continue; };
```

A shell host's `var/run/shells/<id>.sock` is a **real AF_UNIX socket**, and
`std::fs::FileType::is_file()` is **false** for a socket. So `scan_shell_ids`
returns an empty list in production, and everything built on it is inert:

- `adopt_at_startup` adopts **nothing** — a shell that survived a daemon
  restart is never re-registered.
- `sweep_stale` sweeps **nothing** — a dead host's leftover socket/lock is
  never cleaned.

Measured live (isolated `HOME`, `backend = "pty"`, canned-AI stub, real tmux
client):

```
# a chat turn spawned shell s0, then `daemoneye stop` + `daemoneye daemon`:
s0.sock: socket=True regular_file=False      # the live socket
s0.lock: socket=False regular_file=True
shell-host --id s0 : pid 2625986 before stop == pid 2625986 after restart   # host survived
cast: BEG markers: 1  END markers: 1  (…DE_END … 0)                          # log intact, sleep completed
daemon.log after restart: (no "shell registry: adopted" line)               # NOT re-adopted
```

The shell **host** survives the restart (its process, socket, lock and
`.cast` are all intact) — but the daemon comes back blind to it. From the
daemon's side the shell is orphaned forever: never listed, never reaped, never
managed.

## What should happen

`docs/dev/milestones/M20-shell-engine/README.md` § Exit criteria, the PE's
hard requirement: *"with a shell running `sleep 60` under `backend = "pty"`,
`daemoneye stop` then `daemoneye daemon` leaves the shell alive, **re-listed
under the same id**, still logging …"*. Re-listing is the adoption step, and it
does not happen.

`scan_shell_ids` must find a `<id>.sock` entry whether it is a real socket
(production) or a regular file (today's test fixtures). The name grammar —
`.sock` suffix + `ShellId::parse` — is the real gate; the `is_file()` filter
adds nothing correct and excludes the one file type that actually occurs.

## Root cause

The unit tests create their `.sock` fixtures as **regular files**
(`write(dir.path(), "s0.sock")`, `src/shell/registry.rs` ~line 500/519), for
which `is_file()` is true — so the filter passes in every test and fails only
against the real socket in production. Green suite, broken in reality; the
exact gap the live sweep exists to find. Origin is phase-06b, which introduced
`scan_shell_ids` / `adopt_at_startup` / `sweep_stale`.
