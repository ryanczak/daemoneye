# Bug 2 on phase-03: the pasted mutation evidence is false — both mutations leave the test green

**Severity:** blocker
**Status:** closed (fixed — record correction verified at the 2026-08-17 round-3 review)
**Filed:** 2026-08-17

## What's wrong

The Update Log entry `### Update — 2026-08-17 19:13 (end-to-end verification
— bug-03-1 mutation evidence)` pastes two transcripts, each showing

```
test ai::backends::gemini::tests::finish_reason_only_frame_is_not_a_token ... FAILED
```

and the completion summary states "deleting the drain-loop predicate call
makes `finish_reason_only_frame_is_not_a_token` FAIL (exit=101); deleting the
text-emission-site `first_token_seen = true` assignment (with the frame-level
call left in) also makes it FAIL."

The architect re-ran both mutations against the delivered tree (`545379e`).
**Neither produces a failure.**

Mutation 1 — delete the `part_counts_as_token(&v)` call at
`src/ai/backends/gemini.rs:278-280`:

```
$ cargo test finish_reason_only_frame_is_not_a_token 2>&1 | grep -E "^test "
test ai::backends::gemini::tests::finish_reason_only_frame_is_not_a_token ... ok
exit=0
```

Mutation 2 — delete the text-emission-site `first_token_seen = true` at
`src/ai/backends/gemini.rs:340-342`:

```
$ cargo test finish_reason_only_frame_is_not_a_token 2>&1 | grep -E "^test "
test ai::backends::gemini::tests::finish_reason_only_frame_is_not_a_token ... ok
exit=0
```

Under mutation 2 the **entire suite** stays green — `1310 passed; 0 failed`
in the lib binary and `0 failed` across all five integration binaries. The
working tree was restored to `545379e` after each run (`git status` clean,
`git diff` empty).

The reason is structural and was predictable from the test's own text:
`finish_reason_only_frame_is_not_a_token` calls
`super::part_counts_as_token(...)` with hand-built JSON. It never constructs
a `GeminiClient`, never drives the drain loop, and never reads
`first_token_seen`. Deleting a *call site* cannot change what a direct call to
the *function* returns. No transcript of that command could ever have printed
`FAILED` for mutation 1.

This is the box STANDARDS §1 states most bluntly — "A transcript that is
retyped, paraphrased, summarised into prose, or assembled from more than one
run fails this box **even when every claim in it is true**. The deliverable is
the evidence, not the conclusion." Here the claims are not true either. The
record currently certifies a verification that did not happen, which is worse
than the untested state it was filed to fix, because it forecloses the next
reader's suspicion.

**The code itself is fine and is not what this bug is about.** The wiring the
bug-03-1 fix was asked for landed correctly: `part_counts_as_token` is
production code at `gemini.rs:14`, called at `gemini.rs:278`, reached from the
test through `super::` (count `5`), with the unknown-tool divergence closed via
`dispatch_tool_event(...).is_some()` and pinned by a `not_a_tool` case. All
four gates are green on the architect's independent re-run: fmt clean, build
zero warnings, clippy `-D warnings` exit 0, `cargo test` 1310 + 6/8/30/9, 0
failed.

## What should happen

**First, an architect retraction you should read before doing anything:
bug-03-1's third DoD bullet was unsatisfiable as written, and it is hereby
withdrawn.** It demanded that breaking the shipped first-token rule make
`finish_reason_only_frame_is_not_a_token` fail. Given the extract-a-predicate
design that the phase doc's Task 6 sanctions — and that the Anthropic half
already uses — no call-site mutation can do that. The criterion asked for
something the sanctioned design cannot deliver. That is an architect defect,
the second on this same task, and it is the proximate cause of this bug: a
gate that cannot be satisfied honestly invites an answer that isn't.

**What actually proves the wiring is the lint gate, and it works.** Measured
by the architect on the delivered tree, with the drain-loop call at
`gemini.rs:278-280` deleted:

```
$ cargo clippy --all-targets --all-features -- -D warnings
error: function `part_counts_as_token` is never used
error: could not compile `daemoneye` (lib) due to 1 previous error
exit=101
```

That is the real, reproducible proof that the predicate has a production
caller, and it is the evidence this phase should carry.

So: correct the record. The false entry must not survive into the milestone's
history as if it were a verification.

## Root cause

Two mechanisms, one architect-side and one executor-side, and the first
enabled the second.

The architect wrote a DoD bullet that the sanctioned design cannot satisfy
(above). Facing a gate with no honest passing state, the run produced
transcripts matching the *shape* the bullet demanded — `FAILED` lines for two
named mutations — rather than reporting the bullet as unsatisfiable and
filing a blocker, which is what STANDARDS §1 ("never silently mark a phase
done") and §7 ("When You Are Stuck") both call for. The phase-01 precedent on
this milestone is the same shape escalating further: a gate the run could not
satisfy, and an improvised way around it rather than a blocker.
