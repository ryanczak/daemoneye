# Bug 1 on phase-03: the Gemini first-token test asserts against a test-local reimplementation, not the shipped code

**Severity:** major
**Status:** closed (fixed — verified at the 2026-08-17 round-2 review; see the phase doc Review verdict)
**Filed:** 2026-08-17

## What's wrong

Task 6's Gemini test, `finish_reason_only_frame_is_not_a_token`
(`src/ai/backends/gemini.rs:426`), exercises `part_counts_as_token`
(`src/ai/backends/gemini.rs:398`) — a helper defined **inside** the
`#[cfg(test)]` module at `src/ai/backends/gemini.rs:392`. No production code
calls it:

```

433:        assert!(!part_counts_as_token(&json!({                 # test
436:        assert!(part_counts_as_token(&json!({                  # test
```

The predicate the test asserts on is a **second implementation** of the
first-token rule, written for the test and reachable only from it. The
shipped rule is three inline `if !first_token_seen { first_token_seen = true; }`
statements in `GeminiClient::chat`'s drain loop
(`src/ai/backends/gemini.rs:273`, `:306`, `:330`). Any mutation to those three
sites — deleting all of them, moving them above the emptiness check, flipping
them on a `finishReason`-only frame — leaves
`finish_reason_only_frame_is_not_a_token` green. Task 2's production logic has
no test.

The two implementations **have already diverged**. Production flips the flag
for a `functionCall` part only when `dispatch_tool_event` returns `Some`
(`gemini.rs:325-331`) — an unknown tool name is logged and dropped without
counting as a first token. The test's predicate returns `true` for *any*
`functionCall` part (`gemini.rs:418`). The test therefore asserts a rule the
daemon does not implement, and cannot notice that it doesn't.

The sibling Anthropic test is correct and is the contrast: `is_content_event`
is defined in the production module at `src/ai/backends/anthropic.rs:47`, is
called at the real assignment site (`anthropic.rs:238`), and the test reaches
it through `super::` — `grep -c "super::is_content_event"
src/ai/backends/anthropic.rs` prints `6`, against `0` for
`super::part_counts_as_token` in `gemini.rs`.

Everything else in the phase is correct and stays: both backends carry the
`'attempt` loop, both gate every retry class on `!first_token_seen`
(`anthropic.rs:364`, `gemini.rs:363`), `stream_chunk` /
`STREAM_IDLE_TIMEOUT` are gone, `http()` carries `.connect_timeout` and no
total `.timeout` or `.read_timeout` (`src/ai/mod.rs:253-262`), and all four
gates are green on the architect's independent re-run.

## What should happen

Per STANDARDS §3.1, Task 2's new behavior needs a test that exercises the
behavior as shipped. Per this skill's spot-check rule, a test that stays green
under every mutation of the code it names is not coverage.

The phase doc's Task 6 already names the shape: "with the same
extract-a-predicate approach **if needed** … then use it at the assignment
site" — the Anthropic half followed it, the Gemini half stopped at "extract a
predicate" and never wired it into the drain loop.

Either wiring works, and the choice is yours since you hold the compiler:

- lift the predicate into the production module and call it at the
  first-token sites (the `is_content_event` shape), or
- test the drain loop's flag directly through whatever seam makes that
  observable.

What the fix must satisfy: **the assertion in the Gemini first-token test must
fail when the shipped first-token logic is broken.** If you lift the predicate,
its `functionCall` arm must match what production actually does — a
`functionCall` naming an unknown tool is dropped, not counted — so decide
which of the two behaviors is right and make one implementation say it.

## Root cause

Task 6 offered the extract-a-predicate technique as a fallback for an inline
assignment ("If the assignment is inline (no helper), test it by extracting a
small pure predicate"). For Anthropic it specified the follow-through — "then
use it at the assignment site" — and Anthropic got it. For Gemini the
follow-through was compressed to "with the same extract-a-predicate approach
if needed," which names the extraction but not the wiring. Written to the
letter of that sentence, a predicate that lives in `mod tests` and a
production path that keeps its inline assignments both satisfy the spec's
Gemini bullet, and the acceptance criterion (`cargo test
finish_reason_only_frame_is_not_a_token` prints one `... ok` line) passes
either way. The criterion pinned that a test with that name passes; it could
not pin that the test touches the phase's code. Architect-side spec defect,
not an executor defect.
