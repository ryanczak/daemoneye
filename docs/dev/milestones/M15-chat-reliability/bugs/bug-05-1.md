# Bug 1 on phase-05: Esc in the sudo credential panel submits an empty password instead of cancelling

**Severity:** major
**Status:** closed
**Filed:** 2026-08-16 (found by the M15 close live sweep; does not invalidate
M15's written exit criteria — scheduling is PE's call)

> Closed **as deferred, not as fixed** — M15 is done and the repo's bug
> tracker forbids an open bug on a done phase. The defect is real and
> unfixed; it is tracked as follow-up work in `docs/dev/NEXT.md`
> ("Deferred follow-ups"). Re-open by copying this doc into the milestone

## What's wrong

The credential panel renders `[Enter] submit  [Esc] cancel`, but pressing
Esc submits an **empty password**. Live reproduction (2026-08-16, session
`30f6529d`, daemon at HEAD `5d8cdcb`): three consecutive Esc presses in the
panel produced `sudo: Sorry, try again. Password for attempt 2/3`, then
`3/3`, then `sudo authentication failed after 3 incorrect password attempts`
— three failed auth attempts logged against the user's account for what the
UI labelled a cancel.

`prompt_credential_ratatui` (`src/cli/commands/stream.rs:1066-1069`):

```rust
b'\x03' | b'\x1b' => {
    cred_real.clear();
    break;
}
```

Esc clears the buffer and breaks, returning `""` — which the caller sends as
a normal `CredentialResponse`, and the daemon's sudo flow treats as a
password attempt.

## What should happen

Esc ends the credential exchange without consuming an auth attempt: the
foreground sudo command is aborted (same terminal state cleanup as the
attempts-exhausted path), the AI receives a "user cancelled the password
prompt" tool result, and no empty password is ever piped to sudo.

## Root cause

The wire protocol has no cancel signal in the credential exchange:
`CredentialResponse` carries only the credential string, so the client can
only express "cancel" as "submit empty" — and the daemon's sudo
password-attempt loop (`src/daemon/executor/foreground.rs`, the
attempt-counting loop around the `CredentialPrompt` send) cannot distinguish
an empty submission from a typed-but-wrong one. The `[Esc] cancel` label
shipped with the phase-05 panel promises semantics the protocol never had —
the pre-panel prompt had the same clear-and-break shape, so this is a
surfaced pre-existing gap, not a phase-05 regression.

## Definition of done

- [ ] `CredentialResponse` (or a sibling) can express cancellation
      (e.g. `credential: Option<String>` with `None` = cancelled, or a
      `cancelled: bool` field with `#[serde(default)]` — additive shape).
- [ ] Daemon: a cancelled credential exchange aborts the command without
      invoking sudo, emits a tool result stating the user cancelled, and
      never counts an auth attempt (verify via live check: one Esc →
      zero `Sorry, try again` lines, command not executed).
- [ ] Client: Esc sends the cancel form; Enter on an empty buffer still
      submits (some sudo configs accept empty passwords — do not conflate).
- [ ] A test on the daemon-side handling asserts the cancel form produces
      the abort path, not a sudo attempt.
