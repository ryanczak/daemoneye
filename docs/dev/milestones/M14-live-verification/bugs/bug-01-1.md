The real artifact's Section S1 `daemoneye status 2>&1 | head -8` output (part
of `A=/tmp/e2e-m14-01.txt … } >> "$A" 2>&1`) carries 256-color ANSI escape
codes. The pasted block in the Update Log entry has the same three lines with
the escapes stripped and the box-drawing/spacing hand-normalized (`──
RUNTIME ──` vs. the raw `\e[38;5;60m──\e[0m \e[1m\e[38;5;117mRUNTIME\e[0m
\e[38;5;60m──…`, `model           ollama` vs. `\e[38;5;103mmodel         \e[0m
 \e[38;5;60mollama\e[0m`). Every other line in the 108-line block — S2 through
S6, all nine verdict lines — is byte-identical; only this one 3-line span
differs.

That is precisely the failure this milestone's own tooling exists to catch
(`docs/dev/WORKFLOW.md` § "Give the executor a paste-fidelity check it can run
itself" / § "A pasted transcript is a claim, not evidence"): a human-readable
retype of a colorized terminal block, standing in for the raw file bytes, with
the self-check line asserting a match that a re-run does not reproduce.

## What should happen

Per `STANDARDS.md` §1: "Every end-to-end transcript is captured mechanically —
redirect the command's output to a file and paste that file's contents. A
transcript that is retyped, paraphrased, summarised into prose, or assembled
from more than one run fails this box **even when every claim in it is true**."
And per the phase doc's own § Spec task 7: the Update Log entry's fenced block
must be `/tmp/e2e-m14-01.txt`'s contents verbatim, and Section S6's `PASTE
MATCH` / `PASTE MISMATCH` line must reflect an actual diff against that file —
not be written speculatively.

Every claim the transcript makes about the probed behavior (S1 binary
identity, the S2 fixture, the four dispatch-path probes A–D via the real
session JSONL, the `/panes` inspector, S5 teardown and the four gates) was
independently re-verified at review and holds — this bug is scoped to
evidentiary fidelity of the artifact itself, not to the underlying system
behavior it reports on.

## Root cause

The Update Log entry's fenced block was not produced by copying
`/tmp/e2e-m14-01.txt`'s raw bytes into the doc. `daemoneye status`'s renderer
(`src/cli` — see `daemoneye status` output construction) emits 256-color ANSI
SGR sequences unconditionally in this environment, including when its stdout
is piped inside the `{ … } >> "$A" 2>&1` group (no TTY on the pipe), so the
mechanically captured artifact legitimately contains them. The three lines
that differ in the doc read as a human-cleaned rendering of the same visual
content (colors dropped, spacing normalized to what a terminal would display)
rather than a literal paste — the signature § "Give the executor a
paste-fidelity check it can run itself" describes, reproduced here despite the
phase doc shipping that exact self-check as a Spec task.

      doc.
- [ ] The pasted fenced block is diff-clean against the real artifact file
      end-to-end, byte for byte, including any ANSI escape sequences the real
