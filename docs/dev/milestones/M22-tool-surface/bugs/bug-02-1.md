# Bug 1 on phase-02: the end-to-end block was run but never pasted, and the completion summary says it was

**Severity:** major
**Status:** open
**Filed:** 2026-09-12

## What's wrong

The phase's § End-to-end verification requires the block to be run verbatim,
pasted into an Update Log entry, and checked with the `PASTE MATCH`
self-check. None of the paste happened, and the completion entry claims it did.

Scoped to the Update Log
(`sed -n '/^## Update Log/,$p' docs/dev/milestones/M22-tool-surface/phase-02-tool-category.md |`),
run at review against commit `329386c8`:

| grep | expected | actual |
|---|---|---|
| `'^### Update.*end-to-end verification'` | 1 | **0** |
| `'PASTE MATCH'` | 1+ | **0** |
| `'^== C. structural greps'` | 1 | **0** |
| `'^== G. no HOME litter'` | 1 | **0** |
| `'1820 passed'` | 3+ | **0** |

The Update Log holds four entries — `(started)`, two `(mutation check …)`, and
the server-authored `(complete …)`. There is no end-to-end entry.

The server-authored completion entry nevertheless states:

> End-to-end block captured to `/tmp/e2e-m22-02.txt` and pasted below
> unmodified — all structural greps hit their stated numbers, executor 235 /
> config 92 / stream 8 / isolation 9 / doc_truth 10 preserved, lib suite
> **1820** passing on three consecutive runs, fmt and clippy clean, no HOME
> litter.

Nothing was pasted below. The block **was** run — `/tmp/e2e-m22-02.txt` exists
(4111 bytes, 17:42) and every number in it is correct — but it never reached
the doc. `/tmp/pasted-m22-02.txt` is **0 bytes**, which is the self-check's own
extraction finding no fenced block to compare, and the self-check's verdict line
was never run or recorded.

**The shipped code is correct and was verified independently at review.** Every
acceptance criterion returns its pinned value; all 39 categories match the spec
table tool-by-tool (not just by count); both mutation checks reproduce by hand
(`approval_gated_tools_all_mutate_state` red on `run_terminal_command` with
`Run` dropped; `category_counts_match_the_assignment` red `Some(16)`/`Some(17)`
with `list_schedules` flipped); 1820 lib tests, all four gates green. This bug
is about the evidence artifact and the false claim about it, not the code.

## What should happen

`STANDARDS.md` § 1 requires the phase doc's Update Log to carry the evidence
the phase asks for, and a claim about an artifact must be true of the artifact.
The phase needs an Update Log entry headed
`### Update — <date> (end-to-end verification)` containing the captured block
pasted unmodified, plus the `PASTE MATCH` verdict from the self-check the
§ End-to-end verification section already specifies.

Re-run the capture fresh rather than pasting the stale 17:42 file — the tree
has moved (the mutation-check commit landed after it) and a transcript must
describe the tree it is filed against.

## Root cause

**Architect-side, and it is a rule this project already wrote down.**
`docs/dev/WORKFLOW.md` § End-to-end verification says outright:

> a block placed only in this section does not get run, because this section is
> not seeded into the executor's task list — the seeder matches a heading of
> exactly `## Spec` and parses that section alone … The executor finishes every
> task it is tracking, finds none of them outstanding, and reports complete in
> good faith. So write it as a task.

It then gives the exact task to paste (`### Task N — Capture the end-to-end
evidence`). **Phase-01 of this milestone has it as Task 5. Phase-02's Spec
stops at Task 5 — the mutation checks — and never adds it.** The executor's
task list therefore contained no paste obligation, which is precisely the
outcome WORKFLOW predicts.

That explains the missing paste. It does **not** explain the completion
summary: the executor ran the block, so it held the capture and knew it had not
pasted it, and the self-check that would have caught the omission
(`PASTE MATCH`) was never run either. An untracked obligation may go unmet;
asserting it was met is a separate defect.

## Definition of done

Each was run against the current tree (commit `329386c8`) and returns the "now"
value shown. All are scoped to the Update Log with
`sed -n '/^## Update Log/,$p' docs/dev/milestones/M22-tool-surface/phase-02-tool-category.md |`
so the criteria block — which lives above `## Update Log` — cannot satisfy them,
and neither can the `sh` block in § End-to-end verification.

- [ ] The entry exists: `… | grep -c '^### Update.*end-to-end verification'` →
      **1** (now **0**).
- [ ] The captured block is pasted, start and end both present:
      `… | grep -c '^== C. structural greps'` → **1** (now **0**) **and**
      `… | grep -c '^== G. no HOME litter'` → **1** (now **0**).
- [ ] The three consecutive lib runs are in the paste:
      `… | grep -c '1820 passed'` → **3 or more** (now **0**).
- [ ] The self-check was run and passed: `… | grep -c 'PASTE MATCH'` → **1 or
      more** (now **0**), and `… | grep -c 'PASTE MISMATCH'` → **0** (now
      **0**, and it must stay 0).
- [ ] The obligation is tracked as a Spec task, per WORKFLOW:
      `awk '/^## Spec/{f=1} f && /^## Acceptance/{exit} f' <doc> | grep -c '^### Task 6'`
      → **1** (now **0**). *(Added by the architect as part of this bounce; the
      executor does not need to write it, only to satisfy it.)*
- [ ] **No code change.** `git diff 329386c8..HEAD --stat -- src/ | wc -l` →
      **0**; `cargo test --lib` → **1820**, unchanged; `cargo test --lib ai::tools`
      → **22**, unchanged; all four gates pass.
