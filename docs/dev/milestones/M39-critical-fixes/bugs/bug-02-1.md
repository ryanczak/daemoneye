# Bug 1 on phase-02: no test pins the `open_shell` arm's sandbox gate

**Severity:** major
**Status:** open
**Filed:** 2026-11-22

## What's wrong

The fix is right. `dispatch_open_shell.rs` calls `ghost_shell_open_refusal`
first and breaks out of the arm with its refusal. But no test reaches that
call. The gate's four tests (`gate_tests` in `dispatch_open_shell.rs`) call
the pure function `ghost_shell_open_refusal` directly. The two end-to-end
tests (`owner_tests`) run with the sandbox **off**, where the gate passes.

The reviewer ran a mutation to prove it. The arm's
`break 'arm Ok(ToolCallOutcome::Result(r));` was replaced with `let _ = r;`,
which leaves the gate computed and ignored. Then
`cargo test --lib daemon::executor` printed:

```
test result: ok. 485 passed; 0 failed; 9 ignored; 0 measured; 2572 filtered out
```

Every test passes with the phase's main security fix switched off.

The phase doc named the end-to-end test that pins this:
`ghost_open_shell_is_refused_while_the_sandbox_is_on`, driven through
`execute_tool_call` with a ghost session, `[sandbox] enabled = true` in the
temp HOME's config, and a fixture registry, asserting the refusal text and an
empty registry. The executor wrote it and ran it red, which is in the Update
Log. Then it removed the test when it split the tests into `gate_tests` and
`owner_tests`. `cargo test --lib ghost_open_shell_is_refused_while_the_sandbox_is_on`
now runs 0 tests.

A smaller gap: no test asserts that the sandbox-on refusal suggests
`wait: false`, which acceptance criterion 1 requires. The sandbox-on gate test
checks only `r.is_some()`.

## What should happen

A regression that stops the arm from refusing a ghost while the sandbox is
on, or that moves the gate after the shell is spawned, fails a test.
Acceptance criterion 1 asks for exactly that: "No shell is spawned. The
sandbox refusal says why and suggests `wait: false`."

## Root cause

The executor read the end-to-end test's job as "show the red run". Once the
pure gate existed, it treated the arm-level test as redundant. A pure-function
test proves what the gate decides. Only a test through the arm proves the arm
asks it, and asks it before spawning.

## Definition of done

- [ ] `cargo test --lib ghost_open_shell_is_refused_while_the_sandbox_is_on`
      runs **1** test, and it passes. **Fails on the current tree:** it runs 0.
- [ ] That test goes through `execute_tool_call`, not the pure function. With
      the sandbox on it asserts that the result contains `wait: false` and
      that the registry it was given is empty.
- [ ] Mutation check, run by the executor with the output pasted into the
      Update Log: replace the arm's `break 'arm Ok(ToolCallOutcome::Result(r));`
      after `ghost_shell_open_refusal` with `let _ = r;`, run the test, see it
      fail, then restore the line.
- [ ] The lib suite reports **3057** passed (3056 + this test), not 3056.
- [ ] Every other phase-02 criterion still holds. All four gates pass.
