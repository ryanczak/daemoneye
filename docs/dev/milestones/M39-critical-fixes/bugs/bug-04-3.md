# Bug 3 on phase-04: the rule file's name keeps the `.`, so sudo never loads it

**Severity:** blocker
**Status:** closed (fixed by `c71449e8`, verified live on pinky 2026-11-23)
**Filed:** 2026-11-23

## What's wrong

After the bug-04-2 fix, the live probe on pinky (sudo-rs 0.2.13) gets the
whole install right:

```
root:root 755 /usr/local/libexec/daemoneye
root:root 755 /usr/local/libexec/daemoneye/1000
root:root 755 /usr/local/libexec/daemoneye/1000/de-sudo-probe.sh
root:root 440 /etc/sudoers.d/daemoneye-de-sudo-probe.sh
/etc/sudoers.d/daemoneye-de-sudo-probe.sh: parsed OK
```

The grant still fails:

```
$ sudo -k; sudo -n /usr/local/libexec/daemoneye/1000/de-sudo-probe.sh
sudo: interactive authentication is required
```

`install_sudoers` (`src/scripts.rs`, the `safe_name` sanitiser) maps every
character outside `[alphanumeric - _ .]` to `_`. It **keeps** `.`, so the
rule for `de-sudo-probe.sh` goes to
`/etc/sudoers.d/daemoneye-de-sudo-probe.sh`. The installed man page
(`sudoers-rs(5)`) says `@includedir /etc/sudoers.d` reads each file there
"skipping file names that end in '~' or contain a '.' character". sudo
never reads the rule. `visudo -cf <file>` checks the file directly, which
is why it prints `parsed OK` for a file sudo ignores.

This bug predates phase-04, dating from `e070c6fd` (2026-03-24). Every
`install-sudoers` of a script with a `.` in its name has installed a rule
that does nothing. Every script in the README's examples is a `.sh`.

## What should happen

The rule's file name under `/etc/sudoers.d/` contains no `.` and does not
end in `~`, for every script name `validate_script_name` accepts. Two
distinct accepted script names must not share a rule file, so
`fix.sh` and `fix_sh` must not both map to `daemoneye-fix_sh`. The rule's
**content** is unchanged and still names the exact copy path, dot included.
After a real install, `sudo -n <copy>` runs as root with no password.

## Root cause

The sanitiser was written to keep the name readable, and `.` looks
harmless in a file name. The one consumer with a stricter rule is sudo's
`@includedir`. `visudo -cf` doesn't apply that rule, and no test pinned the
installed file name. The plan tests pass `/etc/sudoers.d/daemoneye-fix.sh`
in as a literal, so they never exercised the naming.
