# Bug 1 on phase-01: the round-trip test leaks a tmux server on every run

**Severity:** major
**Status:** closed (2026-11-22, architect takeover)
**Filed:** 2026-11-22

## What's wrong

`format_literal_round_trips_through_tmux` (`src/tmux/pane.rs`, test
module) starts a private server with `new-session -d -s t` on
`<tempdir>/s.sock` and never stops it. The tempdir is deleted when the test
returns, but the tmux server and its shell keep running with no socket
left to reach them. Each `cargo test` adds one. At review, nine were
running on pinky, one per run since the phase started. A review run of
`cargo test` took the count from 8 to 9. The reviewer killed them.

There is a second, smaller problem. The skip probe runs a bare
`std::process::Command::new("tmux").output()` with no arguments, which is
`tmux new-session` against the **ambient** server. The Test plan says:
"The test must use `-S` with its own socket, never the ambient server."
Without a terminal it fails with `open terminal failed`, so it is inert
today, but it is the one call the spec forbids.

## What should happen

The test leaves no process behind, whether it passes or fails. The analogue
the phase doc names, `PrivateTmux` in
`src/cli/program_status_emit_tests.rs`, kills its server on `Drop`. That
covers the panic path an `assert!` takes, which a `kill-server` placed
after the asserts would not. The skip probe must not touch the ambient
server: `tmux -V` needs no server at all.

## Root cause

The test reimplemented the private-server harness as a closure and left
out its `Drop` teardown. The probe was written as "does spawning tmux
work" instead of "is the binary present".

      once does not change the count of
      `pgrep -c -f '^tmux -S /tmp/\.tmp[^/]*/s\.sock new-session'`
      (anchored; the unanchored form first written here also matched the
      shell running it). **Fails
      on the current tree:** the count goes up by 1.
- [x] The teardown runs on the failure path too. Show it: temporarily
      break an assertion, run the test, see it fail, check the count is
      unchanged, then restore the assertion. Paste that red run and the
      count.
- [x] The skip probe runs `tmux -V`, and no tmux call in `src/tmux/pane.rs`'s
      test module runs without `-S`, apart from that probe.
- [x] Every other phase-01 criterion still holds: the five tests pass,
      `grep -c 'display-message' src/webhook/process.rs` prints `0`, and
      clippy and `tests/tmux_read_only.rs` pass.
