# Bug 1 on phase-05: quoted arguments fail closed; wrapper and brace bypasses remain

**Severity:** major
**Status:** closed (fixed in bb87a6f9, verified 2026-11-24)
**Filed:** 2026-11-23

## What's wrong

The architect probed `command_has_sudo` on `9fa1078e`:

```
true  find . -name '*.log'        true  grep 'foo.*bar' f
true  sed 's/a*/b/' f             true  awk '$3 > 5' f
true  echo "$HOME"                true  cd "$dir"
true  jq '.[0]' f                 true  ls "$d"/*.txt
false nohup $S id                 false env $S id
false s{u,}do id                  false {sudo,} id
```

1. **Quoted arguments count as elevation.** `command_has_sudo` rescans every
   quoted region as a command in its own right, and that rescan now applies
   the fail-closed rule. A `$` or glob anywhere inside quotes therefore makes
   the whole command elevating. The spec says these characters change nothing
   in argument position. The cost is concrete: a ghost is refused
   `grep 'a.*b'`, and chat prompts for `cd "$dir"`.
2. **`$` behind a wrapper escapes.** The fail-closed check runs only while
   `at_command` is set, and the wrapper branch never sets it. Because the
   shells persist, a ghost can run `S=sudo` in one command and `nohup $S id`
   in the next.
3. **Brace expansion escapes.** bash expands `s{u,}do` and `{sudo,}` to
   `sudo`, but `{` is not one of the unresolvable characters.
4. **Nit:** the fd-digit check runs twice. The first copy, the
   `chars[i] == '<'` block straight after `read_shell_word`, duplicates the
   later `'<' | '>'` check.

## What should happen

These are the PE's decisions, 2026-11-23:

- **Quoted text** is always scanned for the elevator names, as it was before
  this phase. The fail-closed rule (unresolved `$` or glob) applies inside a
  quoted region only when that region is code a shell will run: the operand
  that follows `-c` for `sh`, `bash`, `dash`, `zsh` or `ksh`, an operand of
  `eval`, or the operand of `su -c`. So `sh -c "$CMD"`, `bash -c 'sud? id'`
  and `eval "$X"` stay `true`, while every quoted argument above goes back to
  `false`.
- **Wrappers:** after a wrapper, a word with an unquoted `$` expansion counts
  as elevation. A glob in that position does not. So `nohup $S id` and
  `env $S id` are `true`, `timeout 10 ls *.txt` stays `false`, and
  `timeout 10 cat $FILE` becomes `true`, which is accepted.
- **Brace expansion:** a command-position word with an unquoted `{…}` that
  contains `,` or `..` is unresolvable. A bare `{`, the keyword in
  `{ sudo id; }`, is unchanged.

## Root cause

The quoted text gathered by `read_shell_word` (`ShellWord.quoted`) is handed
to a recursive `command_has_sudo`. Fail-closed is one of that function's own
rules, so it fires on regex and format strings. The unresolvable branch sits
inside `if at_command`, after the `if wrapper { continue; }` early exit.
`read_shell_word` sets `unresolvable` only for `$ * ? [`.
