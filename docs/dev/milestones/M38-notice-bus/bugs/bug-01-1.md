# Bug 1 on phase-01: removing a closed subscriber reorders inline subscribers

**Severity:** major
**Status:** fixed (architect, 2026-11-16)
**Filed:** 2026-11-16

## What's wrong
`Bus::publish` (`src/bus/mod.rs`) removed closed queued subscribers with
`Vec::swap_remove`, which moves the last subscriber into the freed slot.
With subscribers `[inline first, queued closed, inline second, inline
third]`, the publish after the queued receiver closed ran
`first, third, second`.

## What should happen
Spec task 6: inline subscribers are called "in subscription order", on
every publish.

## Root cause
`swap_remove` is O(1) but not order-preserving; the subscriber list is an
ordered list.

## Definition of done
- [x] `bus_removing_a_closed_subscriber_keeps_inline_order` fails on the
      `swap_remove` tree (observed: `["first", "third", "second"]`) and
      passes after the fix.
