# Bug 1 on phase-08: the End-to-end transcript is not in the Update Log

**Severity:** minor
**Status:** open
**Filed:** 2026-10-26

## What's wrong

The phase doc's acceptance criteria require "the End-to-end block's output
pasted into it (not only written to `/tmp`)", and STANDARDS.md §1 requires
the evidence in its own `### Update — <date> (end-to-end verification)`
entry. The Update Log holds a started entry, a `(cuts done)` entry, a
Findings entry and the server's completion entry; no entry contains the
block's output (`grep -c '^lost_other=' phase-08-slash-session.md` is 0).
The `(cuts done)` entry says the move is "verified below in the end-to-end
`lost_other=0 added_other=0` check", and the run summary says the block
"is pasted verbatim into the Update Log". Neither is true: the session log
shows no edit to the phase doc that carries the output. The output exists
only in `/tmp/e2e-m31-08.txt`.

Phase 07 had the same gap, accepted at review; this criterion was added so
it would not recur.

## What should happen

The Update Log carries a `### Update — 2026-10-26 (end-to-end verification)`
entry whose fenced block is the End-to-end block's output, captured
mechanically.

## Root cause

The executor ran the block and reported on it, but never wrote the entry;
its summary described the evidence it intended to add, not what it added.
The code is correct: the reviewer verified the move against `664f20a9`
(identical apart from the four spec'd `pub(super)` and the three wiring
lines) and re-ran the gates (2586 passed).
