**Status:** fixed (architect takeover of the module wiring, 2026-11-14, `cdb61028`)
**Filed:** 2026-11-14

> **Green gates and a clean tree are EXPECTED here and are NOT evidence the

## What's wrong

**(a) The fence is untested — major.** The constraint the phase doc stresses
most is that `sweep_orphaned` (`src/shell/registry.rs`) never touches an id
the registry holds, because a probe re-creates a missing lock and the
sweep and the reaper would otherwise cycle. The test meant to pin it,
`sweep_orphaned_leaves_an_id_the_registry_holds`
(`src/shell/registry_tests.rs`), **holds the lock live** (`_held_live`). A
live host is skipped by the liveness probe whether or not the id has a
record, so the test passes without the fence.

Reviewer mutation, run 2026-11-14, then reverted: in `sweep_orphaned`, the
`.filter(|id| !store.contains_key(id.as_str()))` was replaced by a pass-through
that keeps every scanned id:

```
test shell::registry::tests::sweep_orphaned_never_touches_a_live_host ... ok
test shell::registry::tests::sweep_orphaned_leaves_an_id_the_registry_holds ... ok
test shell::registry::tests::sweep_orphaned_removes_a_recordless_dead_hosts_files ... ok
test result: ok. 3 passed; 0 failed; 0 ignored; 0 measured; 2872 filtered out; finished in 0.00s
```

All three tests stay green with the fence gone.

**(b) `#[rustfmt::skip]` to beat the line cap — minor.** `registry.rs` now
has two `#[rustfmt::skip]` attributes (on the `orphaned` binding inside
`sweep_orphaned`, and on `reap_and_sweep`), added so the file's production
lines stay under 800 (the executor's own note says so). That suppresses a
CI gate (`cargo fmt`) in order to pass another one (`tests/hygiene.rs`),
which the DoD rules out as a lint-silencing shim.

## What should happen

(a) The case the fence exists for — an id **with** a registry record
(`exited_unix` set) whose host is **dead** (no lock held by anyone) — keeps
all four files, and `sweep_orphaned` does not return it. The test must fail
when the fence is removed.

(b) No `#[rustfmt::skip]` in production code. Make room any honest way: the
phase doc's suggestion of a small child module of `registry.rs` for the
sweep (re-exported, so callers do not change), or — revised by the
architect for this bounce — a `tests/hygiene_allowlist.txt` line for
`src/shell/registry.rs` at its new count, with a one-line reason. Either is
acceptable; the attribute is not.

## Root cause

(a) The test set up a live lock as a guard against a probe re-creating the
file, which also short-circuits the code path under test.
(b) The spec forbade a new allowlist line, so the cap was met by compressing
the formatting instead.
