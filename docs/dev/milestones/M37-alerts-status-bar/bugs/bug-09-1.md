## What's wrong

**(a) The test plan is unimplemented.** `cargo test` passed=2998, the same
count as before the phase. Not one of the ten tests the phase doc names
exists:

```
$ for t in wide_form_carries_the_words words_drop_all_at_once_before_any_rank_drop \
    state_and_alert_words_survive_every_drop an_idle_default_bar_has_no_grants_and_reads_idle \

    grep -rlw "fn $t" src || echo "missing: $t"; done
missing: wide_form_carries_the_words
… (all ten missing)
```

The diff to `status_bar_tests.rs` edits existing assertions to the new
strings (`⚡ grants 4`, `! gated`, no `⏱`). It adds no test of the words-drop
step, the exemptions, the plurals, the `all` word, the dialects, the
no-doubling constraint or the width bound.

**(b) No evidence.** The completion entry says the mutation check and the
§ End-to-end block "could not be run" (the run hit its turn budget). The
phase's acceptance criteria require both, pasted.

**(c) The wide counters contradict the spec.** `counter_parts` builds the
wide text as `format!("{w} {count}")` (`src/cli/status_words.rs:136`), so a
counter reads word-then-count (`🐚 shells 2`, `👻 ghosts 2`, `⏳ bg 2`). Task
3's table specifies count-then-word: `⏳ 2 bg`, `👻 1 ghost` / `👻 2 ghosts`,
`🛠 3 tools`, `🐚 2 shells`. The completion note states the order as an
adaptation. The constraint it cites, no doubled words in ascii, allows the
word to replace the glyph, but it does not allow a different word order.
Hosts in the grants segment follow the same rule (`🌐 2 hosts`). The
`scripts 2` / `files 2` / `grants 3` / `turn 7` / `ctx 2%` forms stay
label-then-value, as the table says.

Phase-09 § Test plan, § Acceptance criteria and task 3's table.

The run spent its budget on the implementation and the existing-test
updates, then reported complete without the test plan or the evidence. The
word order came from one generic helper for every counter.
