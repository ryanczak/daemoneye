# Bug 1 on phase-12: the words still never appear, and the sign dialects still double the `$`, the `/h` and the `t/s`. The snapshot tests pin all three bugs

**Severity:** blocker
**Status:** open
**Filed:** 2026-11-15

> Already approved, do not redo: the rank constants with `RANK_WORDS` between
> the alert age and the session, `counters_slot` (one counters slot), the move
> of the drop loop into `status_bar_fit.rs`, the removal of `cost_untracked`,
> the `»`/`›` and `⚉` glyphs, the emoji `💰?0.42`, the docs (decision 8), and
> the new `status_bar_snapshot_tests.rs` file and its fixture.

## What's wrong

Every expected string in `src/cli/status_bar_snapshot_tests.rs` was pasted
from the code's output without checking it against the Goal. The tests are
green and the bar is wrong:

1. **No word except the state word ever renders, at any width.** The 160-column
   emoji line still carries the grants detail and every velocity, yet reads
   `🌓20%`, `↻12`, `🦙 deepseek-v4`. The Goal requires `🌓 ctx 20%`,
   `↻ turn 12`, `🦙 model: deepseek-v4`, `🐚 3 shells`. The PE's setup
   (`snapshot_emoji_info_alert_no_grants_unnamed_at_160_and_80`) has no `ctx`,
   `turn` or `shells` at 160. The Goal says the words must show there **and**
   at 120, and the test never renders 120. Acceptance criterion 4 fails.
2. **The sign dialects still double the sign or suffix.** The symbols and
   ascii lines at 160 read `$?0.42 $/h0.2/h`, and the ascii line reads
   `t/s38t/s`. Spec tasks 3 and 4 require `?0.42`, `$0.2/h` and `38t/s`.
   Defect 2 of the Goal is unfixed.
3. **`snapshot_words_survive_the_grants_detail_and_velocities` asserts no
   word.** It checks `idle` (the state word, which never drops) and the
   compact `↻12`. It would pass with the words gone, so mutation check (a)
   proved nothing about the words.

## What should happen

- When the full wide line does not fit, ranks 1–5 drop **in the wide form**
  first. The words drop (`wide = false`) only when the loop reaches
  `RANK_WORDS` and the line still does not fit (phase task 1, decision 8 A).
  At any width where every rank-1–5 part has dropped and the wide line fits,
  every word is present.
- Wherever the dialect's glyph already *is* the sign or the unit, it appears
  once, in both forms. Symbols/ascii cost: `?0.42` unknown, `$0.42` known.
  Symbols/ascii burn: `$0.2/h` compact, `$0.2/h burn` wide. Ascii throughput:
  `38t/s` compact, `38 tok/s` wide. Emoji forms are as the Goal states.
- Every pinned snapshot string is read against the Goal before it is pasted.
  A pinned line containing `$?`, `$$`, `/h0` or `t/s` followed by a digit,
  or a 160-column line with velocities present and no `ctx`, is wrong.

## Root cause

1. `status_bar_line` (`src/cli/status_bar.rs`) still seeds
   `let mut wide = line_fits(…, true, width)`. When the full wide line
   overflows (it does at 160 with grants), `wide` starts `false`, and
   `drop_loop` (`src/cli/status_bar_fit.rs`) then measures the compact line
   first. That line fits, so the loop breaks at once with nothing dropped.
   This is the old pre-step decision under a new name: the words drop before
   any rank does.
2. `two_form` (`src/cli/status_words.rs`) builds the compact form as
   `glyph + compact_value`. `cost_parts` passes `?0.42`/`$0.42`, burn passes
   `0.2/h`, and `turn_parts` passes `38t/s`, each already carrying the sign or
   unit, behind a glyph (`$`, `$/h`, `t/s`) that carries it too. The
   `spelled` flag added for ascii throughput only changes the wide form.
