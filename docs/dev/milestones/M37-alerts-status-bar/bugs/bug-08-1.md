# Bug 1 on phase-08: the attach path's new file I/O makes the suite leak into the real `$HOME`, and the two new attach tests fail when run on their own

**Severity:** major
**Status:** open
**Filed:** 2026-11-15

> **The full `cargo test` is green (passed=2998) and that is NOT evidence the
> phase is done.** The new tests pass in the full suite only by scheduling
> luck. Already approved, do not redo: the production code in
> `src/daemon/away_digest.rs`, `src/daemon/scheduled.rs` and the
> `handle_chat_attach` wiring in `src/daemon/server/chat_presence.rs`; the
> docs; the `away_digest` unit tests and both mutation checks.

## What's wrong

**(a) Tests write the developer's real state.** `handle_chat_attach` now calls
`take_away_digest_on_attach` and `stamp_on_last_detach`, which read the event
log and write `var_run_dir()/chat_last_seen` under whatever `$HOME` the
process has. Several tests drive the real `handle_chat_attach` without
`crate::test_home_guard()` and a throwaway `$HOME`: the `attach` helper's
callers in `src/daemon/server/chat_presence.rs` tests (for example
`presence_unregisters_when_the_hold_ends_in_error`), the attach tests in
`src/webhook/process.rs` and `src/daemon/scheduled_tests.rs`, and
`tests/integration.rs` (around lines 1379–1510). Reproduced by the reviewer:

```
$ rm -f ~/.daemoneye/var/run/chat_last_seen
$ timeout 600 cargo test --test integration 2>&1 | grep '^test result'
test result: ok. 40 passed; 0 failed; 2 ignored; ...
$ ls ~/.daemoneye/var/run/chat_last_seen
/home/<user>/.daemoneye/var/run/chat_last_seen
```

A real `chat_last_seen` stamped by a test run moves the window the live
daemon's first digest reports.

**(b) The two new attach tests only pass with the right neighbours.** Run on
their own, they fail every time (3 of 3):

```
$ timeout 600 cargo test --lib chat_presence 2>&1 | grep -E '^test .*FAILED|^test result'
test daemon::server::chat_presence::tests::attach_joins_the_digest_to_the_brief_in_one_system_msg ... FAILED
test daemon::server::chat_presence::tests::the_last_detach_stamps_last_seen ... FAILED
test result: FAILED. 23 passed; 2 failed; 0 ignored; 0 measured; 2883 filtered out
```

with `the digest rides the same message: [Catch-up] …` (no digest delivered)
and `the stamp moved forward to the close time: 1794714030 < 1794717630`.

## What should happen

Phase-08 § Constraints: "Tests are hermetic: `crate::test_home_guard()`
plus a throwaway `$HOME` … A test that calls `handle_chat_attach` must keep
the presence map clean." No test touches the real `$HOME`, and each new test
passes run alone, filtered, or in the full suite.

## Root cause

The presence map is process-global. The new tests hold `test_home_guard`, but
the existing attach tests that run in parallel do not, so they are not
serialized against the new ones. Their live connections make
`live_presence_connections()` (`away_digest.rs:280`) exceed 1, so the
digest is withheld, and `presence_session_ids()` is non-empty at the new
test's detach, so the stamp is not taken. Those same unguarded tests, and
the integration tests, run with the real `$HOME`, which is where the stamp
lands. The phase made a previously file-free path do file I/O without
making every caller of that path hermetic.
