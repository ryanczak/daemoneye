# Bug 1 on phase-04: the non-fence branch was widened, not preserved — an unterminated backtick span now extracts

**Severity:** minor
**Status:** open
**Filed:** 2026-07-31

## What's wrong

Spec task 1 requires that outside a fence the extractor "run the existing
backtick-span logic on that line, **unchanged**." The rewrite dropped the
`on_line` guard, so the non-fence path is no longer behaviour-preserving.

Before (`extract_path_literals`, pre-721224a), a backtick span that hit a
newline before its closing backtick was **discarded**:

```rust
if ch == '\n' {
    on_line = false;
    break;
}
...
if on_line {           // <- span kept only if it closed on the same line
    let trimmed = span.trim();
```

After (`src/config/path_audit.rs:236-250`), the inner loop simply runs to end
of line and the span is kept unconditionally:

```rust
while let Some(&ch) = chars.peek() {
    if ch == '`' { chars.next(); break; }
    span.push(ch);
    chars.next();
}
let trimmed_span = span.trim();     // <- no on_line check; unterminated spans kept
if PATH_PREFIXES.iter().any(|&pfx| trimmed_span.starts_with(pfx)) {
```

Verified at review by appending a temporary probe test to the module:

```
input:  "see `var/log/unterminated.txt\nnext line\n"
PROBE_RESULT=["var/log/unterminated.txt"]     // old behaviour: [] (span discarded)
```

The probe was removed and the file restored (`git checkout`) before the
gate re-run.

This matters because it widens the gate in the one direction the phase doc
says it must not go. "Current state" states the audit must keep exiting 0 on a
clean tree, "a gate that fires on a correct tree gets disabled" — and the
"Line-by-line processing is behaviour-preserving" section justifies the whole
rewrite on the claim that a per-line scan is *equivalent*, precisely because
newline-spanning spans were already discarded. The implementation falsifies
that claim. A doc line with an odd number of backticks ahead of a path-like
token now produces a literal that previously never reached `classify_text`.

No current asset triggers it: the seeded-assets regression test passes and
`clean-audit-exit=0` reproduces at review. This is a latent widening, not a
live false positive — hence minor rather than major.

No test pins the behaviour in either direction, so nothing would catch a
future regression here.

## What should happen

The non-fence branch extracts a span only when that span is closed by a second
backtick on the same line, matching the pre-phase behaviour the spec called
"unchanged" and the phase doc's own equivalence argument.

## How to fix

In `src/config/path_audit.rs`, in the `else` (non-fence) arm of
`extract_path_literals`:

1. Restore the closed-span guard. Track whether the inner loop exited because
   it consumed a closing backtick, and keep the span only in that case — e.g.
   set a `closed = false` before the inner loop, set it `true` on the
   `ch == '`'` break, and gate the `found.push` on it. (A per-line scan never
   sees `\n`, so the guard is about *termination*, not about newlines.)
2. Add a test pinning it, e.g. `unterminated_backtick_span_is_discarded`:
   assert `extract_path_literals("see `var/log/unterminated.txt\nnext\n")`
   returns an empty vec. Pair it with the existing
   `inline_backticks_still_extracted_outside_fences` so both directions are
   held.

Do not otherwise touch the fence branch, `PATH_PREFIXES`, `normalise`,
`classify_text`, or `INVENTORY` — everything else in this phase reviewed
clean, including both mutation probes (see the review verdict).
