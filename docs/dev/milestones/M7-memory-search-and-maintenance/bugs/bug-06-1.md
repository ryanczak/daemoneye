# Bug 1 on phase-06: the three `HOME` tests reuse fixed `/tmp` paths, so `open_index_creates_database_and_schema` stops testing creation after its first run

**Severity:** minor
**Status:** fixed
**Filed:** 2026-08-01

## What's wrong

`src/memory/index.rs:67`, `:90`, `:102` each point `HOME` at a **fixed, shared,
never-cleaned** path instead of a fresh temporary directory:

```rust
unsafe { std::env::set_var("HOME", env::temp_dir().join("daemoneye-test-index-1")) };
unsafe { std::env::set_var("HOME", env::temp_dir().join("daemoneye-test-index-2")) };
unsafe { std::env::set_var("HOME", env::temp_dir().join("daemoneye-test-index-3")) };
```

Nothing removes these, so they survive the test process. Verified at review:

```
$ rm -rf /tmp/daemoneye-test-index-*
$ cargo test --lib memory::index      # test result: ok. 6 passed
$ ls -d /tmp/daemoneye-test-index-*
/tmp/daemoneye-test-index-1
/tmp/daemoneye-test-index-2
/tmp/daemoneye-test-index-3
$ ls -l /tmp/daemoneye-test-index-1/.daemoneye/var/index/memory.db
-rw-r--r-- 1 matt matt 24576 Aug  1 12:00 …/memory.db
```

**The consequence is a test that stops testing.**
`open_index_creates_database_and_schema` asserts:

```rust
let conn = open_index().expect("open_index should succeed");
let path = crate::config::memory_index_path();
assert!(path.exists(), "database file should exist at {}", path.display());
```

On the first run in a clean environment that genuinely proves `open_index()`
created the database. On **every subsequent run** the file is already on disk
before the test body starts, so `path.exists()` is true regardless of what
`open_index()` did — the assertion cannot fail. On any machine that has run the
suite once (every developer box, every warm CI runner), the test's headline
claim is no longer under test.

Two smaller consequences from the same cause:

- **Litter.** Three directories containing SQLite databases accumulate in `/tmp`
  and are never cleaned up.
- **Collision.** Two checkouts, or two CI jobs, running the suite concurrently on
  one host share these paths. `crate::test_home_guard()` serialises threads
  *within* a process; it does nothing across processes.

The production code is correct and all six tests pass — this is a test-strength
defect, not a behaviour defect.

## What should happen

Each test that repoints `HOME` gets its **own** temporary directory, removed when
the test ends, so every run starts from a genuinely empty tree and
`open_index_creates_database_and_schema` proves creation every time.

## How to fix

Use the idiom the phase spec pointed at — `src/config/path_audit.rs:543` and
`:866`, inside `inventory_contains_all_config_constructors`:

```rust
let _guard = crate::test_home_guard();
let tmp = tempfile::tempdir().unwrap();
unsafe { std::env::set_var("HOME", tmp.path()) };
```

`tempfile::tempdir()` returns a `TempDir` that deletes the directory on drop, so
binding it to a live local (`tmp`, not `_`) for the body of the test is the whole
cleanup story — no manual teardown. `tempfile = "3"` is already a dev-dependency
(`Cargo.toml:46`).

Apply to all three of `open_index_creates_database_and_schema`,
`open_index_sets_schema_version` and `open_index_is_idempotent`. Keep
`crate::test_home_guard()` — it is still required, and it must be taken *before*
`set_var`. Do not change the other three tests; they use
`Connection::open_in_memory()` and never touch `HOME`.

Strengthen the creation test while you are in it: assert the database does
**not** exist before calling `open_index()`, then that it does after. That is
what makes the fix self-enforcing rather than a cleanup that a later edit can
silently undo:

```rust
let path = crate::config::memory_index_path();
assert!(!path.exists(), "fresh HOME must not already have an index");
let conn = open_index().expect("open_index should succeed");
assert!(path.exists(), "open_index must create {}", path.display());
```

## Explicitly NOT a finding — do not "fix" these

- **`#![allow(dead_code)]` at `src/memory/index.rs:3` stays.** It is required,
  not cosmetic: `memory` is `pub(crate)` (`src/lib.rs`), so `SCHEMA_VERSION`,
  `open_index` and `ensure_schema` are genuinely unreferenced until phase 07
  calls them, and without the attribute `cargo clippy -- -D warnings` fails with
  three `never used` warnings (reproduced at review). The phase spec asked for an
  API that nothing calls yet under a deny-warnings gate and did not say how to
  resolve that — an architect spec gap, not an executor defect. The executor
  flagged it in its own summary, which is the right behaviour. **Phase 07 must
  delete this attribute** once the functions are wired in; that is recorded in
  `NEXT.md` and will be pinned in phase 07's spec.
- **The schema, the DDL, and the six test names** are all per spec. Leave them.

Fixed: replaced all three tests with `tempfile::tempdir()` which auto-cleans on drop, and strengthened `open_index_creates_database_and_schema` to assert the database is absent before `open_index()`. Commit 2afae23.
