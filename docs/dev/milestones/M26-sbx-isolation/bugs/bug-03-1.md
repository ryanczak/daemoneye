# Bug 1 on phase-03: an unknown runtime suppresses the profile checks

**Severity:** minor
**Status:** fixed (`e028057f`, verified 2026-10-06)
**Filed:** 2026-10-06

## What's wrong

`SandboxConfig::warnings()` (`src/config/types.rs`) returns early after the
unknown-runtime warning:

```rust
if self.runtime != "docker" && self.runtime != "sbx" {
    out.push(format!(
        "[sandbox] runtime = {:?} is not supported — use \"sbx\" (or \"docker\", \
         until it is removed)",
        self.runtime
    ));
    return out;
}
```

The `return out;` skips **rule 4 (profiles)** as well as rules 2–3. With
`runtime = "podman"` and a profile `bad` whose `network = "bogus"`,
`warnings()` returns **1** warning (measured). The invalid profile is never
reported.

## What should happen

Phase doc § Spec, Task 1:

- rule 1: "An unknown runtime adds **no other runtime-specific** warnings
  (skip rules 2 and 3)";
- rule 4: "Profiles, **for every runtime including an unknown one**".

So that config must give **2** warnings: the runtime one first, then
`profile.bad … is invalid`.

Rule 4 also limits the "equivalent to \"none\"" message to
`runtime == "docker"`. Today that branch is reachable only because the early
return hides the unknown-runtime case. Once the profile loop runs for an
unknown runtime, the branch must not fire for it either.

## Root cause

The early `return` makes rule 4 conditional on a known runtime. The spec makes
only rules 2–3 conditional. The phase's own
`sandbox_warnings_reject_unknown_runtime` test could not catch it: its
profile (`proxy`, empty `proxy_allow`) produces no warning under any rule
for `podman`.

## Definition of done

- [ ] New test `sandbox_warnings_unknown_runtime_still_checks_profiles` in
      `src/config/mod.rs` (`// ── SandboxConfig ──` group): `runtime =
      "podman"`, one profile `bad` with `network = "bogus"` → exactly 2
      warnings, the first containing `podman`, the second `profile.bad`.
      It **fails** against the current tree (1 warning).
- [ ] `sandbox_warnings_reject_unknown_runtime` still passes, unedited: an
      unknown runtime with a `proxy` profile and an empty `proxy_allow` gives
      exactly 1 warning, so the "equivalent to none" branch must stay
      docker-only.
- [ ] All other `config::tests::sandbox*` tests pass unchanged.

## How to fix (measured by the reviewer, 2026-10-06)

Two edits in `SandboxConfig::warnings()`, run against the current tree; all
sandbox tests plus a probe of the case above pass:

1. Delete the `return out;` after the unknown-runtime warning. Rules 2 and 3
   are already gated on `self.runtime == "docker"` and
   `self.runtime == "sbx"`, so they stay skipped for an unknown runtime.
2. Gate the empty-allow branch on docker:
   `} else if network == "proxy" && self.runtime == "docker" && profile.proxy_allow.is_empty() {`
