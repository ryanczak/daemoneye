# Bug 2 on phase-01: completion Update Log is missing the required "End-to-end verification" section

**Severity:** major
**Status:** verified
**Filed:** 2026-07-09
**Resolved:** 2026-07-09 (session takeover)

## Resolution

Both E2E scenarios from the phase doc were run against the real
`target/debug/daemoneye` binary and their output recorded in the phase-doc
completion Update Log:
- **Write path** — a real daemon run wrote `var/log/events/events-<today>.jsonl`
  (containing the `daemon_start` event) and did not create the legacy
  `var/log/events.jsonl`.
- **Read path** — `daemoneye costs --since 2019-01-01 --json` over a legacy
  file ($1.25) plus a dated segment ($2.50) reported `total_cost_usd: 3.75`
  with both groups surfaced.

Note: the phase doc's E2E prose said `var/events*`; the implemented paths are
under `var/log/` (`var_log_dir()`), which is what was verified.

## What's wrong

`STANDARDS.md` §1 (Definition of Done) requires:

> Every acceptance criterion that references a real artifact the phase ships
> ... has been **verified end-to-end against that real artifact** — not just
> against a unit-test fake — and the actual output is quoted in the
> completion Update Log entry under "End-to-end verification." A green
> `cargo test` run that exercises a temp-directory-scoped fake is **not** by
> itself sufficient.

The phase doc itself (`phase-01-events-rotation.md`) has its own
`## End-to-end verification` section spelling out two concrete steps to run
and quote:

1. Run a daemon action that triggers `daemon_start`/`daemon_stop`, then
   `ls $HOME/.daemoneye/var/events/` and quote the listing plus one line of
   content.
2. Seed a legacy file + a dated segment with `ai_cost` fixtures, run
   `target/debug/daemoneye costs --json`, and quote the output showing both
   segments aggregated.

The completion Update Log entry (`### Update — ts=1783646972515 (complete,
server-authored)`) contains only a "Command output tails" section with
`cargo fmt` / `cargo build` / `cargo clippy` / `cargo test` output. There is
no "End-to-end verification" heading anywhere in the phase doc, and no
quoted output from running the real `target/debug/daemoneye` binary against
real fixtures on the real filesystem.

All of the phase's new tests (`segments_enumerate_legacy_first`,
`sum_cost_between_spans_segments`, `sweep_deletes_only_expired_segments`,
etc.) are exactly the "temp-directory-scoped fake" the DoD explicitly calls
insufficient by itself — they're real fs operations, but they're still
`cargo test`, not a run of the compiled binary.

Note for the record: I (the reviewer) ran scenario 2 myself against
`target/debug/daemoneye costs --json` with a legacy-file + dated-segment
fixture as part of this review, and the cross-segment cost total is correct
(`3.75` from `1.25 + 2.50`). That confirms the underlying mechanism works,
but it does not substitute for the executor performing and documenting the
verification — and it does not cover scenario 1 (the daemon actually
writing to `var/events/events-<today>.jsonl` from a real process, not a
test) at all, which remains unverified end-to-end.

## What should happen

The phase's completion Update Log entry must contain a literal
`## End-to-end verification` (or equivalently named) section quoting the
real output of both scenarios named in the phase doc's own
"End-to-end verification" section, run against the compiled
`target/debug/daemoneye` binary with `HOME` pointed at a scratch directory
— not against a `#[cfg(test)]` fixture.

## How to fix

Run, and quote verbatim in the phase doc's Update Log:

```sh
HOME=$(mktemp -d) target/debug/daemoneye status   # or another command that
                                                    # triggers daemon_start/stop
ls $HOME/.daemoneye/var/events/
cat $HOME/.daemoneye/var/events/events-<today>.jsonl   # at least one line
```

and

```sh
# seed $HOME/.daemoneye/var/log/events.jsonl (legacy) and
# $HOME/.daemoneye/var/log/events/events-<today>.jsonl (dated) with
# ai_cost fixture lines, then:
target/debug/daemoneye costs --json
```

quoting the JSON output showing both segments' costs summed.
