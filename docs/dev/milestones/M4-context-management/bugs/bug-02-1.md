# Bug 1 on phase-02: Blind-spot fix is a no-op — calibrated estimate computed then discarded

**Severity:** major
**Status:** verified
**Filed:** 2026-07-13
**Verified:** 2026-07-14 (fix `cb92cd3` — effective_prompt_tokens wired into
`token_pct` + `PromptCtx`; `_effective_prompt_tokens` binding removed; gates green)

## What's wrong

Spec task 4 (the post-restart blind-spot fix, one of the phase's two stated
deliverables — D15-partial / D10-partial) is not wired in. In
`src/daemon/server/ask.rs:239-259` the calibrated estimate is computed but
bound to a **discarded** variable:

```rust
let (last_prompt_tokens, _effective_prompt_tokens) = if let Some(ref id) = session_id {
    ...
            if lpt > 0 {
                (lpt, lpt)
            } else {
                let est = crate::daemon::context::estimate::estimate_history_tokens(&messages);
                let scaled = (est as f64 * ts).min(u32::MAX as f64) as u32;
                (0, scaled)          // <-- last_prompt_tokens stays 0; scaled goes to a `_`-prefixed binding
            }
    ...
};
```

The leading underscore on `_effective_prompt_tokens` suppresses the
`unused_variables` lint — which is why clippy `-D warnings` stayed green while
the value is dead. Downstream, `token_pct` reads the raw `last_prompt_tokens`:

```rust
let token_pct = if context_window > 0 {
    (last_prompt_tokens as f64 / context_window as f64 * 100.0) as u32   // ask.rs:277 — 0 in the blind-spot case
} else { 0 };
```

In the blind-spot branch `last_prompt_tokens == 0`, so `token_pct` computes to
0 and compaction is still blind for the post-restart turn — the exact defect
this phase was meant to fix. The `PromptCtx` construction at `ask.rs:525` also
receives the raw `last_prompt_tokens`, so the `[BUDGET]` line is blind too.

The unit tests pass because they only exercise the pure helper
(`estimate_history_tokens` / `update_token_scale`); no test drives the `ask.rs`
branch, so the dead wiring is invisible to `cargo test` (STANDARDS §1: a green
test run over a fake is not sufficient).

## What should happen

Per Spec task 4: the calibrated `effective_prompt_tokens` must **drive** the
compaction decision when `last_prompt_tokens == 0`. Specifically:

- `token_pct` is computed from `effective_prompt_tokens`, not the raw
  `last_prompt_tokens`.
- `PromptCtx.last_prompt_tokens` (ask.rs:525) receives `effective_prompt_tokens`
  so the `[BUDGET]` line is not blind either.

When `last_prompt_tokens > 0`, `effective_prompt_tokens == last_prompt_tokens`,
so there is no behavior change on the normal path (acceptance criterion 4 stays
satisfied).

## How to fix

In `src/daemon/server/ask.rs`, collapse the pair into a single
`effective_prompt_tokens` value and use it in both consumers:

```rust
let effective_prompt_tokens: u32 = if let Some(ref id) = session_id {
    if let Ok(guard) = sessions.lock() {
        if let Some(entry) = guard.get(id.as_str()) {
            if entry.last_prompt_tokens > 0 {
                entry.last_prompt_tokens
            } else {
                let est = crate::daemon::context::estimate::estimate_history_tokens(&messages);
                (est as f64 * entry.token_scale).min(u32::MAX as f64) as u32
            }
        } else { 0 }
    } else { 0 }
} else { 0 };
```

Then:
- line ~277: `(effective_prompt_tokens as f64 / context_window as f64 * 100.0) as u32`
- line ~525: pass `effective_prompt_tokens` into `PromptCtx`.

Remove the `_effective_prompt_tokens` binding entirely — no underscore-suppressed
value should remain.

Add a test that actually pins the branch (the current tests miss it): construct
a fresh `SessionEntry` (`last_prompt_tokens == 0`, `token_scale == 1.5`,
non-empty history) and assert the value fed to `token_pct` is non-zero. If the
compaction decision cannot be unit-tested without a daemon, extract the
"resolve effective prompt tokens" step into a small pure helper in
`daemon/context/estimate.rs` (e.g. `effective_prompt_tokens(last: u32, scale:
f64, history: &[Message]) -> u32`) and test that helper directly — mirroring how
the phase already keeps its logic in testable pure functions.
