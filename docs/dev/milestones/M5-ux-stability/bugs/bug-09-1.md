# Bug 1 on phase-09: `liveness_is_not_running_when_peer_closes_immediately` never reaches the EOF branch

**Severity:** minor
**Status:** verified
**Filed:** 2026-07-29

## What's wrong

The test named for the EOF row of task 1's mapping table does not exercise it.
It passes via the **`write_all` failure** arm instead, so `Ok(Ok(0)) =>
DaemonLiveness::NotRunning` is implemented but **uncovered**.

Proven by mutation, three runs, at review:

| Mutation to `daemon_liveness()` (`src/daemon/mod.rs`) | Result |
|---|---|
| `_ => Unresponsive` → `NotRunning` | `liveness_is_unresponsive_when_peer_never_replies` **FAILED** (correct) |
| `Ok(Ok(0)) => NotRunning` → `Confused` | **all 9 passed** ← the EOF branch is dead to the suite |
| `if tx.write_all(…).is_err() { NotRunning }` → `Confused` | `liveness_is_not_running_when_peer_closes_immediately` **FAILED** |

The third row is the proof of *which* path it takes.

The cause is a race in the test's sequencing (`src/daemon/mod.rs`, in the
`#[cfg(test)] mod tests` block):

```rust
        let probe = tokio::spawn(async { daemon_liveness().await });

        // Accept then immediately drop the stream — EOF.
        let (stream, _) = listener.accept().await.unwrap();
        drop(stream);
```

The peer closes before the probe's `write_all` completes, so the probe fails on
the write rather than reading EOF. Both arms return `NotRunning`, so the
assertion holds either way and the test cannot distinguish them.

**Attribution: this test design came from the phase doc's Test plan** ("accept,
then drop the stream → `NotRunning` (the EOF row of the task-1 table)"), which
did not account for the write racing the close. The executor implemented what was
specified. The production code is correct and needs no change.

## What should happen

The EOF row must be genuinely covered, per `STANDARDS.md` § 3 and `WORKFLOW.md`
§ "Coverage claims are inadmissible without mutation proof" — a test named for a
branch must fail when that branch is broken.

## How to fix

In `src/daemon/mod.rs`, in `liveness_is_not_running_when_peer_closes_immediately`,
make the peer **consume the request first** so `write_all` succeeds, then close to
force EOF:

```rust
        let probe = tokio::spawn(async { daemon_liveness().await });

        // Read the probe's Ping first so its write_all succeeds, THEN close —
        // otherwise the close races the write and the probe fails on the write
        // instead of reading EOF, leaving the Ok(Ok(0)) arm uncovered.
        let (mut stream, _) = listener.accept().await.unwrap();
        use tokio::io::AsyncReadExt;
        let mut buf = vec![0u8; 256];
        let _ = stream.read(&mut buf).await;
        drop(stream);

        let liveness = probe.await.unwrap();
        assert_eq!(liveness, DaemonLiveness::NotRunning);
```

Do **not** change `daemon_liveness()` itself — its mapping is correct.
Do **not** add a test for the `write_all` arm; it is already covered (row 3
above), just by a differently-named test. Renaming is optional and not required.
