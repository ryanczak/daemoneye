# Bug 1 on phase-10: the "leading prefix" ordering claim is false — invariant and test both assert it

**Severity:** minor
**Status:** verified
**Filed:** 2026-07-30

## What's wrong

**Root cause is an architect error in the phase spec.** Task 1 claimed insertion
order into `serde_json::Map` controls serialized key order:

> Leading position keeps `ts` / `event` / `pid` as a stable prefix on every line,
> which is what makes `grep` and `jq` over a segment readable.

That is wrong. Without the `preserve_order` feature — which this crate does not
enable (`Cargo.toml:33`, `serde_json = "1.0.149"`, no features) — `serde_json::Map`
is a `BTreeMap`, so **keys serialize in alphabetical order regardless of insertion
order**. Verified against a real record written by this phase's own E2E daemon:

```json
{"event":"daemon_start","pid":3122741,"session":"daemoneye","socket":"/home/matt/.daemoneye/var/run/daemoneye.sock","ts":"2026-07-30T05:15:08.083282913+00:00","version":"0.9.9"}
```

`ts` is **fifth of six**. There is no `ts,event,pid` prefix and there cannot be one.

**The executor caught this and declared it** in its summary — correct behavior — but
two artifacts still assert the false property:

**1. The `CLAUDE.md` invariant** (written verbatim from the spec, `CLAUDE.md`
§ "Important Invariants"):

```markdown
- Every `events.jsonl` record carries `ts`, `event`, and `pid` as a leading
  prefix; `log_event` stamps `pid` itself, so call sites must not pass one.
```

This is durable guidance. Anyone writing a parser or `grep` on the strength of
"leading prefix" is misled.

**2. `log_event_prefix_order_is_ts_event_pid`** is vacuous. Proven by mutation at
review — moving the `pid` insert to *after* the drain loop:

| Test | Result under the mutation |
|---|---|
| `log_event_caller_pid_overrides_stamp` | **FAILED** ✓ (genuinely pins the ordering) |
| `log_event_prefix_order_is_ts_event_pid` | **passed** ← detects nothing |
| `log_event_stamps_emitting_pid` | passed |

It asserts `event < pid < ts < z_custom`, which holds by the alphabet alone. The
sentinel is named `z_custom`, so the comparison can never fail no matter what the
code does.

**What is correct and needs no change:** the `pid` stamp itself, its
insert-before-drain position, and `log_event_caller_pid_overrides_stamp`, which
does catch the mutation the spec asked to be caught.

## What should happen

Documentation and test names must state properties the code actually has, per
`WORKFLOW.md` § "Coverage claims are inadmissible without mutation proof" and
§ "Specs pin behavior, not rendering". The real, useful guarantee is
**presence**, not position.

## How to fix

**Two edits. Do not touch `log_event`'s body or `log_event_caller_pid_overrides_stamp`.**

### 1. Correct the `CLAUDE.md` invariant

Replace the bullet with:

```markdown
- Every `events.jsonl` record carries `ts`, `event`, and `pid`; `log_event` stamps
  `pid` itself, so call sites must not pass one. Key **order** in the serialized
  line is `serde_json`'s (alphabetical — this crate does not enable
  `preserve_order`), so never rely on field position when parsing a record.
```

### 2. Replace the vacuous ordering test with a presence test

Rename `log_event_prefix_order_is_ts_event_pid` to
**`log_event_always_stamps_ts_event_and_pid`** and assert presence of all three
plus the caller's own field, rather than byte offsets:

```rust
    #[test]
    fn log_event_always_stamps_ts_event_and_pid() {
        with_test_home(|| {
            log_event("presence_test", serde_json::json!({"custom": "val"}));
            let seg = crate::config::current_event_segment_path();
            let content = std::fs::read_to_string(&seg).unwrap();
            let line = content.lines().next().unwrap();
            let record: serde_json::Value = serde_json::from_str(line).unwrap();
            // Presence, not position: serde_json::Map is a BTreeMap here
            // (no `preserve_order`), so serialized key order is alphabetical
            // and insertion order is not observable in the output.
            assert!(record.get("ts").is_some(), "ts missing");
            assert!(record.get("event").is_some(), "event missing");
            assert!(record.get("pid").is_some(), "pid missing");
            assert_eq!(record["event"], "presence_test");
            assert_eq!(record["custom"], "val");
        });
    }
```
