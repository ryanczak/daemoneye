# Bug 2 on phase-01: Prompt text becomes invisible when the live region is exactly 4 rows tall

**Severity:** minor
**Status:** open
**Filed:** 2026-07-25

## What's wrong

`render_prompt_region` now renders the prompt string into the reserved spinner
rect, but that rect is zero-height whenever the region is shorter than
`MIN_HEIGHT_FOR_SPINNER_ROW`. At a region height of exactly **4** the function
still takes its full-render path, so the prompt is rendered into a zero-height
rect and silently disappears.

`src/cli/render_ratatui.rs:512-533`:

```rust
    let (spinner_rect, body) = split_spinner_row(area);

    // Reserve 1 row for status bar, 2 for input box, rest for prompt.
    let total = body.height;
    if total < 4 {
        // Too small — fall back to normal input region.
        …
        return;
    }
    let chunks = Layout::vertical([Constraint::Min(1), Constraint::Length(1)]).split(body);

    // ── Prompt text in the reserved spinner row ────────────────
    …
    frame.render_widget(prompt_para, spinner_rect);   // ← height 0 when area.height == 4
```

Walk the two guards at `area.height == 4`:

- `split_spinner_row` — `4 < MIN_HEIGHT_FOR_SPINNER_ROW (5)`, so it returns
  `spinner_rect` with `height: 0` and `body == area` (height 4).
- the fallback guard — `total` is `4`, which is **not** `< 4`, so the function
  does **not** fall back and proceeds to the full render.

The result is an input box and a status bar with no prompt text. This is a
regression: the previous three-way split gave `prompt_rows = total - 3 = 1` at
this height, so the prompt was visible.

The user-visible consequence is a sudo password prompt, or a tool-approval
prompt, that renders as an empty box with no indication of what is being asked.
`draw_prompt` is the path used for credential entry
(`src/cli/commands/stream.rs:931`) and approval prompts (`:779`), so the
failure mode is "the terminal is asking for a password and does not say so."

Reachable in a tmux pane 4 rows tall — uncommon but not exotic, and the inline
viewport clamps to the terminal height, so `frame.area().height` really can be
4 even though `VIEWPORT_ROWS` is 6.

## What should happen

At every region height, either the prompt is visible or the renderer falls back
to a layout that does not promise one. There must be no height at which
`draw_prompt` renders a box with no prompt.

## How to fix

> **AMENDED 2026-07-25 — the original "How to fix" in this doc was wrong, and
> the fix currently on disk implements it. Read this section, not the run's
> memory of the old one.**
>
> The original text prescribed adding `|| spinner_rect.height == 0` to the
> fallback guard, routing height-4 to `render_live_region`. That was a bad
> instruction: **`render_live_region` has no `prompt` parameter and never
> renders the prompt string** (`src/cli/render_ratatui.rs:432-440`). So the
> prescribed fix moves the height-4 case onto a different code path that *also*
> shows no prompt — the user-visible defect is unchanged. It also made the
> stated verification ("assert the buffer contains `password:`")
> unsatisfiable, which is why the test that shipped asserts only that a `┌` is
> present, and why that test's doc comment contains the false claim that the
> fallback "does render the prompt text in the buffer via the input box."
>
> Architect's error, not the executor's. Fix it as described below.

The prompt must be visible at **every** height where `draw_prompt` renders
anything at all. At heights too short to reserve the spinner row, the prompt is
more important than either the stable-box property (meaningless at 4 rows) or
the input echo — the old pre-phase code made the same trade.

Implement three branches in `render_prompt_region`:

```rust
    let (spinner_rect, body) = split_spinner_row(area);

    if area.height < 4 {
        // Genuinely too small for prompt + box + status — existing fallback.
        let it: ratatui::text::Text<'_> = input_text
            .split('\n')
            .map(|l| Line::from(Span::raw(l)))
            .collect();
        render_live_region(frame, area, &it, session_id, model, start_time, None);
        return;
    }

    // Rows the prompt, box and status bar are drawn into. When the reserved
    // spinner row exists (height >= MIN_HEIGHT_FOR_SPINNER_ROW) the prompt
    // takes it and the box keeps its stable row. When it does not, carve a
    // one-row prompt strip off the top of `body` instead — the box shifts, but
    // at this size a visible prompt matters more than a stable box.
    let (prompt_rect, rest) = if spinner_rect.height > 0 {
        (spinner_rect, body)
    } else {
        let split =
            Layout::vertical([Constraint::Length(1), Constraint::Min(1)]).split(body);
        (split[0], split[1])
    };

    let chunks = Layout::vertical([Constraint::Min(1), Constraint::Length(1)]).split(rest);
```

Then render the prompt into `prompt_rect`, the input box into `chunks[0]`, and
the status bar into `chunks[1]` — the same three renders as today, only the
rects change.

Do **not** reintroduce the old unconditional three-way split. At heights >= 5
the prompt must still go in the reserved spinner row, or
`input_box_row_is_stable_across_draw_modes` fails.
