# Bug 1 on phase-04: the profile's strengths table still carries the `MODEL` column

**Severity:** minor
**Status:** fixed (2026-10-21, `7f16cbfd`)
**Filed:** 2026-10-21

## What's wrong

Spec task 2 says the profile's strengths table is "the scorecard's
columns without `MODEL`". `print_profile` in `src/cli/commands/profile.rs`
calls `render_scorecard_table(&profile.strengths.rows, by)`, which always
emits `MODEL` first, so every strengths row repeats the model the header
already names:

```
Profile of claude-sonnet-4-6 — 4 run(s), 2020-01-01 – now (by kind)
MODEL              KIND   RUNS   PASS  ...
claude-sonnet-4-6  chat      3  33.3%  ...
```

The README paragraph the phase added says the column is absent, so the
README is wrong about the tree too.

## What should happen

The profile's strengths table starts at the `--by` column (`KIND`,
`AGENT` or `TAG`) and has no `MODEL` column. The scorecard's own table is
unchanged. Both still come from one renderer (spec task 3), so the
alignment fix is not duplicated.

## Root cause

`render_scorecard_table` has no way to leave a column out, and
`print_profile` calls it as the scorecard does.

- [x] `daemoneye profile <model>` human output has no line starting with
      `MODEL` (`prof_model_col=0`; it is `1` against the current tree) and

      `0` today).
- [x] `daemoneye scorecard` still prints `MODEL` first

- [x] `long_model_names_keep_columns_aligned` and the full suite pass.
