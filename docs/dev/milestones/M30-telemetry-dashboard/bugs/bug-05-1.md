# Bug 1 on phase-05: the first costed call of a day is counted twice in the ledger

**Severity:** major
**Status:** open
**Filed:** 2026-10-21

## What's wrong

`cost::emit_cost` (`src/cost.rs`) appends the `ai_cost` line with
`log_event` and *then* calls `spend::record(cost)`. When the ledger has
not been seeded for today — the daemon's first costed call, or the first
one after local midnight — `record` (`src/daemon/spend.rs`) seeds it from
the events on disk, and that seed sums every `ai_cost` line from local
midnight to now. The line just written is inside that window (its `ts`
was stamped a moment before `now`, and `for_each_event_between` keeps
`from <= ts <= to`). `record` then adds the same cost on top.

So the daemon's first call of the day lands in `spent_today()` twice. A
$0.50 call reads as $1.00. Every later call that day is counted once,
which is why the executor's end-to-end numbers looked right.

## What should happen

`spent_today()` after any `emit_cost` equals the sum of today's `ai_cost`
lines on disk — on a cold ledger as on a warm one. This number is what
`[budget] max_cost_per_day` will gate on in the next phase, so a
double-counted first call would trip the cap early every morning.

## Root cause

A seed that already contains a record, and an add of that same record,
both happen inside one `record()` call on the cold path. The phase's test
`emit_cost_logs_ai_cost_and_feeds_the_ledger` reads `spent_today()` for
`before` first, which warms the ledger, so the cold path is never
exercised.

## Definition of done

- [ ] A test `the_first_record_of_a_day_is_counted_once` exists and passes:
      a record that triggers the seed leaves the total equal to the seed
      that already includes it, not seed plus the cost. Pure-core test on
      `Ledger` is fine; it must fail against the bounced tree (paste the
      red run).
- [ ] `emit_cost_logs_ai_cost_and_feeds_the_ledger` and the full suite
      still pass; the `ai_cost` line is written exactly once.
