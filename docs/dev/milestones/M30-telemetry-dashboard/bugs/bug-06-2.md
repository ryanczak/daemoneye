# Bug 2 on phase-06: the scheduled-refusal test builds the state it asserts on

**Severity:** minor
**Status:** fixed (2026-10-21, `a7728e41`)
**Filed:** 2026-10-21

## What's wrong

`a_refused_watchdog_ends_the_scheduled_run_budget_exceeded`
(`src/daemon/scheduled.rs`) builds a `RunState::BudgetExceeded` with
`Briefing::new(..)` inline and then asserts that its fields are the ones
it just set. `run_scheduled_job` builds its own copy of that state in a
`match refusal`. The test never runs the code it names, and it would
still pass if `run_scheduled_job` ignored the refusal.

## What should happen

The choice between the refusal state and `scheduled_terminal_state` lives
in one pure function that `run_scheduled_job` calls, and the test calls
it. This is the same shape as the existing `scheduled_terminal_state`
tests.

## Definition of done

- [x] The test builds no state itself: `Briefing::new` appears 0 times in
      its body (`sched_test_builds_state=0`; it is `1` today).
- [x] `run_scheduled_job` calls the same function. The test passes, and
      asserts that `None` gives the state `scheduled_terminal_state`
      would have given.
