# Bug 7 on phase-12: the header clock test races the wall clock

**Severity:** minor
**Status:** open
**Filed:** 2026-10-24

## What's wrong
`screen_header_clock_is_the_draw_time` (`src/cli/commands/top_tui.rs`)
draws, then formats `Local::now()` and asserts the frame holds that
`HH:MM:SS`. A second boundary between the two fails the test. Its negative
check looks for `00:00:00`, but `taken_at` is `00:00:00Z`, which renders in
the local zone, so under any non-UTC zone the check passes against the
buggy code too.

## What should happen
STANDARDS: tests are deterministic. The test proves the header shows the
draw time and not `taken_at`, without depending on when it runs.

## Root cause
`draw` reads the wall clock itself, so the test cannot fix the time.

## Definition of done
- [ ] `screen_header_clock_is_the_draw_time` gives the draw a fixed clock
      and asserts that time appears and `taken_at`'s does not. The harness
      prints `clock_test_wall=0`: the test body does not call `Local::now`.
