# Bug 1 on phase-12: the live header never refreshes

**Severity:** major
**Status:** open
**Filed:** 2026-10-24

## What's wrong
`run_tui` (`src/cli/commands/top_tui.rs`) fetches the header's daemon facts
once, in `take_snapshot`. The 2 s refresh re-asks only for shells, and
`model.snapshot.daemon` is never replaced. The disk refresh saves and
restores `model.snapshot.taken_at`, so it never advances either. `draw`
renders the header clock from `taken_at`. On the live screen the clock and
the uptime freeze at launch, and a daemon that stops keeps showing its pid.

## What should happen
Spec item 1: the header facts are fetched on the same 2 s cadence as the
shells, and the header names the current local time.

## Root cause
The shells branch of the `run_tui` loop calls `shells_panel()` alone. The
header clock reads `snapshot.taken_at`, which the loop deliberately keeps.

## Definition of done
- [ ] The step that applies a shells refresh also asks `Request::Status` and
      replaces `snapshot.daemon`, and it is a function a test drives without
      a daemon. `shells_refresh_replaces_the_daemon_header` passes.
- [ ] The header clock is the time of the draw, not `taken_at`.
      `screen_header_clock_is_the_draw_time` passes: a model whose
      `taken_at` is an hour old draws a header without that hour's time.
