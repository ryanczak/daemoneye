# Bug 1 on phase-07: Activity drops every event that is not `ai_cost`, `budget_refused` or `run`

**Severity:** major
**Status:** open
**Filed:** 2026-10-22

## What's wrong

`activity_row` (`src/cli/commands/top.rs`) has summary arms for `ai_cost`,
`budget_refused` and `run`. For any other event name it returns `None`
(`_ => return None`), and `last_activity` keeps only the rows that return
`Some`. Every other event the daemon writes therefore never reaches the
panel. Reproduced against `9374ae69`: a fixture of `ghost_started`,
`webhook_alert` and `ai_cost` lines prints only the `ai_cost` line under
`Activity`.

So the Activity panel is a cost log, not the events tail.

## What should happen

The Spec says the panel holds "the last 50 events of today, oldest first.
Each one is a time, the event name and a one-line summary". The milestone
exit criterion is "Activity (the events tail, filterable)". Every event
appears.
- The three known kinds keep their summaries.
- Any other kind gets a generic one-line summary drawn from its fields.
  It must be bounded in length and must never be empty.
- An event with no `event` name may still be skipped.
- `--filter` behaves as now.

## Root cause

The fallthrough arm of `activity_row` returns `None` instead of a generic
summary.

- [ ] A test `activity_keeps_every_event_kind` (it does not exist today)
      folds an `ai_cost`, a `budget_refused` and two events of kinds the
      code has no arm for. All four land in the activity rows, each with a
      non-empty summary.
- [ ] On the § End-to-end fixture's two extra lines,
      `activity_other=2` (`0` against the current tree).
- [ ] The existing `activity_lines`, `filtered_refusals` and
