# Bug 2 on phase-12: the fade dims the line above the finished run

**Severity:** major
**Status:** fixed (2026-10-24, 3179c9e3)
**Filed:** 2026-10-24

## What's wrong
`draw` maps faded run indices to display lines with
`runs_body.lines().nth(*i)` (`src/cli/commands/top_tui.rs`). Line 0 of
`runs_text` is the column header, so run `i` is body line `i + 1`. The
lookup dims the line above each faded run: a faded first run dims the
`ID KIND SUBJECT …` header and leaves itself bright. The match is also by
line text, so two identical lines would both dim.

## What should happen
Spec item 4: the lines of runs where `run_fades` is true are drawn dim, and
only those. The selected line stays reversed.

## Root cause
An off-by-one between run indices and body line indices, hidden because no
test draws a faded run.

## Definition of done
- [ ] `screen_dims_only_finished_runs` passes. On an 80×24 `TestBackend`
      with a `Live` run and a `Done` run aged 600 s, the `Done` run's line
      carries `Modifier::DIM`, and neither the column header nor the live
      run's line does.
