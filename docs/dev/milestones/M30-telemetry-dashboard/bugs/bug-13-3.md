# Bug 3 on phase-13: the live loop still re-measures heights only on resize

**Severity:** major
**Status:** fixed (2026-10-25, b8a032bf)
**Filed:** 2026-10-25

## What's wrong
Bug 13-1's first half is not fixed. `run_tui` (`src/cli/commands/top_tui.rs`)
calls `refresh_heights` at startup and when the terminal size changes. After
a disk refresh and after `shells_refresh` it calls only `hold_activity` and
`clamp_offsets`, so the stored heights still go stale when runs or shells
are added. The run's summary says the loop re-measures "after every
disk/shells refresh"; the code does not.
`stored_heights_match_the_drawn_layout` calls `refresh_heights` itself
after growing the content, so it passes without the loop doing it.

## What should happen
Bug 13-1 and spec item 6: the stored heights match the drawn layout after
any content refresh, with no resize in between.

## Root cause
The loop's refresh steps are inline in `run_tui`, and no test runs them.

## Definition of done
- [ ] Each refresh the loop applies goes through one function that holds
      the Activity anchor, re-measures the stored heights and clamps the
      offsets. `run_tui` calls `clamp_offsets()` only through it: the
      harness prints `loop_clamps=0`.
- [ ] `content_refresh_re_measures_heights` passes. It drives that
      function, not `refresh_heights`, with a disk refresh that grows the
      runs from 2 to 20 and a shells refresh that grows them from 1 to 10.
      After each, with no resize, the stored heights equal the drawn ones.
