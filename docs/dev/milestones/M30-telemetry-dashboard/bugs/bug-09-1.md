# Bug 1 on phase-09: an overflowing panel shows the wrong rows — Activity never shows new events, a scrolled-to run goes off-screen

**Severity:** major
**Status:** open
**Filed:** 2026-10-22

## What's wrong

`draw_panel` (`src/cli/commands/top_tui.rs`) renders each body as a
`Paragraph` from its first line, with no scroll offset. Two panels
overflow:

- **Activity.** `activity_text` lists rows oldest first, so a full panel
  shows the *oldest* rows that fit. Reproduced with the real binary in a
  private tmux at 120×40 and 30 `ai_cost` events (`model01`…`model30`):
  the screen shows `model01` to `model17`, and `model30` is absent. A live
  view whose Activity panel never shows a new event is wrong. The doc
  comment on `TopModel::filtered_activity` also says "newest first", but
  the function returns oldest first.
- **Runs.** The block is a fixed `Constraint::Length(10)`, which fits the
  header and 7 rows. `top` lists up to 20 runs, and Down moves the
  selection to any of them. Past the 7th row the reversed line is drawn
  outside the panel, so scrolling stops showing anything, and a followed
  live run past row 7 is invisible too.

## What should happen

Phase-09 Spec item 3: Activity "shows the newest rows that fit". Spec
item 2 makes Up/Down move the selection, which only means something if
the selected row stays visible. When a panel's body is taller than the
panel, Activity shows its newest (last) rows, and Runs scrolls so the
selected row is on screen. The column header stays visible.

## Root cause

`draw_panel` has no notion of which part of an overflowing body matters.
It needs a per-panel rule: the tail for Activity, a window around
`selected` for Runs.

## Definition of done

- [ ] On the phase doc's § End-to-end harness, `tui_newest=1`. It reads
      `0` against the current tree (verified 2026-10-22).
- [ ] `activity_panel_shows_the_newest_rows` passes: a `TestBackend` at

      first's.
- [ ] `selected_run_stays_on_screen` passes: with 20 runs and the
      selection moved to the last row, that row's id is in the buffer, and
      so is the `ID` header.
- [ ] `filtered_activity`'s doc comment states the real order.
