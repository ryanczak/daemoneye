# Bug 1 on phase-06: a call that seeds the ledger is now never counted

**Severity:** major
**Status:** open
**Filed:** 2026-10-21

## What's wrong

`Ledger::record_with_write` (`src/daemon/spend.rs`) now seeds *before* the
`ai_cost` line is written, as the Spec asked. But it kept phase 05's
rule, "skip the add when a seed ran and the line was written". That rule
was right only when the seed ran *after* the write and so already held
the line. Now the seed cannot hold the line, so the call's cost is
dropped. The cold `None` branch of `record_under_lock` does the same (it
adds only when `!line_written`).

Phase 05 counted the first call of a day twice. This tree counts it zero
times. Every call routed through the gate warms the ledger first, so the
loss shows only when emit is the first ledger touch of the day: local
midnight falling between a call's gate and its `emit_cost`, or the first
call of a daemon's life on a path that has no gate in front of it. The
cap gates on this number.

The test meant to pin the order, `seed_runs_before_the_line_is_written`,
calls the no-write `Ledger::record`, so there is no write in it to order.
It asserts the total equals the seed alone (`0.25`), which writes the
undercount down as the expected result. It passes against the phase-05
tree unchanged, so it was never red. The Spec said "the total is the seed
plus the cost, exactly once" and "it fails against the current tree".

## What should happen

`spent_today()` after any `emit_cost` equals the day's `ai_cost` lines on
disk, whether the ledger was cold or warm.

## Root cause

The seed-skip condition was carried over from the old write-then-seed
order without being re-derived for seed-then-write.

## Definition of done

- [ ] `seed_runs_before_the_line_is_written` drives the production form
      that takes the write: its order log holds both `"seed"` and
      `"write"` with the seed first, and the total is seed plus cost
      (`seed_test_writes` ≥ 1; it is `0` against the current tree).
- [ ] A test `the_first_record_after_a_seed_is_added` (it does not exist
      today) covers the cold path of the global entry point's pure core:
      a cold record with `line_written = true` leaves the total at seed
      plus cost. Paste its red run against this tree.
- [ ] The full suite passes.
